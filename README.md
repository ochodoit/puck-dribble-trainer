# 🏒 퍽 드리블 트레이너

아이패드 카메라로 **흰 바닥(연습판)·스틱·퍽을 실시간 인식**해 화면에 겹쳐 보여주고,
장애물 피하기와 스틱핸들링 트레이닝을 진행하는 웹 앱입니다. 프레임워크·외부 라이브러리 없이
순수 HTML/CSS/JS(ES Modules)로 만들어졌고, 홈 화면에 추가하면 전체화면 앱처럼 동작합니다(PWA).

## 디자인

미니멀·타이포그래피 중심. 종이색 바탕 + 잉크 블랙 + **포인트 레드 한 색**으로 통일했습니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| Paper | `#F4F1EA` | 바탕, 카드, 플레이 중 영상 위 워시 |
| Ink | `#161616` | 글자, 얇은 선(1.5px), 장애물 도형 |
| Red (PANTONE 179 C) | `#E03C31` | 포인트: 플레이어의 퍽, 시작 버튼, 필기체 악센트, 경고 |
| Yellow (PANTONE 123 C) | `#FFC72C` | 수집 아이템(황금 퍽) 전용 |

- 글꼴: 제목·숫자는 굵은 세리프(Fraunces / Noto Serif KR), 본문은 Poppins / Noto Sans KR, 악센트는 필기체(Caveat / Nanum Pen Script, 항상 레드). Google Fonts에서 불러오며, 오프라인이면 시스템 글꼴로 대체됩니다.
- 버튼·라벨은 알약형 테두리, 이모지 대신 번호(01–07)와 타이포로 구분합니다. 번호는 **게임 7종에만** 붙입니다(모드 창의 가운데 ‘퍽 대기’ 칸과 커뮤니티 칸은 번호 없음).
- **표기 규칙**: 한국어 화면의 창 제목·버튼·상태 표시(HUD, 결과, 기록 알림, 글 꼬리표)는 모두 한국어로 씁니다. 영문은 로고(Puck Dribble Trainer)와 게임 카드의 작은 부제(ARCADE, WIDE DRIBBLE …, 게임 소개 페이지의 영어 이름과 같음)에만 둡니다. 영어 화면은 `src/i18n-en.js` 사전이 같은 자리를 영어로 바꿉니다.
- 캔버스(게임 화면)도 같은 토큰을 씁니다: `src/theme.js` ↔ `style.css :root`. 색을 바꾸려면 두 곳의 값을 함께 바꾸세요.
- 플레이 중에는 영상 채도를 낮추고 하단 버튼을 걷어 화면을 비웁니다(우하단 "중지"만 남김).
- **배경 투명도**: 설정의 "배경 투명도 %" 슬라이더로 영역 안에서 배경을 보며 하는 게임(퀵 핸즈·반응 타겟)과 와이드 드리블에서 카메라 영상이 비치는 정도를 정합니다(아케이드·퍽 피하기·8자 드리블·자유 연습은 흰 화면 고정. 와이드 드리블도 0~100% 슬라이더대로 비치고, 1% 이상이면 퍽 투명도는 0 고정 — `src/main.js` `visualRules`). 0%는 종이색으로 완전히 덮고, 100%는 영상이 그대로 보입니다(기본 12%). 슬라이더 옆 **미리보기**에 실시간 카메라 영상 위로 바로 보이므로, 게임에 들어가지 않고도 맞출 수 있습니다(설정 창이 열려 있는 동안 게임은 멈추고 미리보기만 움직입니다). 또 슬라이더를 **끄는 동안만**(손가락·마우스를 누르고 있는 동안) 설정 창이 비켜서 끄는 슬라이더 한 줄만 남고, 뒤로 지금 모드의 실제 게임 화면이 바뀐 값으로 보입니다 — 작은 미리보기가 잘 안 보이는 휴대폰용. 손을 떼면 설정 창이 돌아옵니다(내 퍽 투명도 슬라이더도 같음).

## 게임 규칙: 시간과 점수

- **제한 시간 동안의 점수로 겨룹니다.** 기본 1분, 모드 화면에서 3분·5분으로 바꿀 수 있습니다(아케이드·퍽 피하기·와이드 드리블·퀵 핸즈에 적용. 와이드 드리블은 3가지 훈련을, 퀵 핸즈는 3시·6시·9시 3세트를 이 시간씩 이어서 하므로 1분이면 모두 3분. 나머지 드릴은 고유 시간).
- **목숨은 없습니다.** 충돌하면 감점(아케이드 쉬움 −3·보통 −5·어려움 −6, 퍽 피하기 −50)되고 콤보(아케이드는 연속 터치)가 초기화되며 잠깐 무적이 됩니다. 시간이 끝날 때까지 계속 플레이합니다.
- **랭킹은 시간별로 따로** 집계됩니다(아케이드 1분, 아케이드 3분 … 은 서로 다른 순위표). **투명 모드** 기록도 일반과 따로 집계됩니다(랭킹 화면의 `일반 / 투명 모드`).
- **난이도(쉬움·보통·어려움)는 모드 창 제목 줄**에서 시간 옆에 고릅니다. 아케이드·퍽 피하기에만 적용되고, **랭킹도 난이도별로 따로** 집계됩니다(랭킹 키 예: `arcade@60-hard`, 보통은 예전 키 그대로 `arcade@60`). 랭킹 화면에서도 난이도를 고를 수 있습니다. 기록 자랑 글은 보통 난이도 기록만 올릴 수 있습니다.
- 퍽 추적을 0.6초 넘게 놓치면 게임과 시계가 함께 멈추고, 다시 보이면 이어집니다.
- **게임이 끝나면** 결과 화면에서 퍽 위치로 고릅니다. 퍽을 **왼쪽 영역에 2초** 두면 결과를 닫고 가운데 원으로 돌아가고(원에 3초 두면 바로 시작, 카운트다운은 한 번만), **오른쪽 영역에 2초** 두면 모드 선택으로 갑니다. 결과 창 안의 트랙에 퍽의 좌우 위치가 빨간 점으로 보이고, 선택지가 채워지며 실행됩니다. 결과가 뜬 뒤 1.5초는 세지 않고, **결과가 뜰 때 퍽이 있던 쪽은 한 번 가운데로 옮겼다가 와야** 셉니다(게임이 끝난 자리 때문에 저절로 고르는 일 방지). 가운데에 두면 아무 일도 일어나지 않고, 화면을 눌러도 됩니다(핸즈프리 설정을 끄면 터치만). 결과 버튼은 창 아래에 붙어 있어 결과가 길어도 늘 보입니다.
- **중지 버튼으로 멈추면** 결과 화면에서 퍽으로 고르지 않고(버튼만), 결과를 닫은 뒤에도 퍽이 가운데 원 안에 그대로 있으면 다시 시작하지 않습니다. 원 밖으로 뺐다가 다시 넣으면 3초 뒤 시작합니다.
- 0점은 최고 기록(‘최고 기록!’)으로 치지 않습니다.
- **게임 선택 화면은 3×3 배치**입니다. 게임 7개에 01~07 번호를 붙이고, 가운데 칸은 퍽이 대기하는 자리(‘퍽 대기’)라 비워 두었고, 오른쪽 아래 칸은 번호 없이 점선 테두리로 구분한 **커뮤니티**입니다(아래 참고).
- **모드 선택 화면도 퍽으로** 고릅니다. 퍽의 좌우·앞뒤 위치가 카드 목록 위의 빨간 커서가 되고, 카드 가운데 쪽에 2초 머물면 그 모드가 선택됩니다(카드 아래에 진행 띠 표시). 카드 테두리 근처(가로·세로 14%)는 어느 카드도 아닌 것으로 봐서, 카드 사이를 지나갈 때 엉뚱한 카드가 골라지지 않습니다. 화면이 열릴 때 커서가 올라가 있던 카드는 한 번 벗어났다가 다시 와야 선택됩니다. 시작 준비(3/3 움직여 보기)가 끝나 열린 모드 창에서는 퍽을 **가운데 칸(puck, 빨간 고리)에 한 번 둔 뒤에야** 카드를 고릅니다 — 마지막 표적(바닥 모서리) 자리가 모서리 카드(아케이드 등) 위라서 아케이드가 저절로 골라져 시작되던 것을 막습니다. 게임 시간(1·3·5분)과 2인 대결은 터치로 바꿉니다.

## 카메라 없이 체험 · 운영자 화면

**카메라 없이 체험하기** (누구나): 첫 화면 "카메라 시작" 바로 아래 버튼. 처음 온 사람이 카메라·퍽 없이 먼저 해 보게 합니다. 기록·랭킹·출석·기록 자랑에는 안 들어가고, 결과 화면에 "체험 기록은 저장되지 않아요" 와 **카메라로 하기**(첫 화면으로) 버튼이 나옵니다. 세로로 든 휴대폰이면 판도 세로(9:16)로 화면을 채웁니다. 운영자 테스트도 같은 모드를 씁니다.

운영자 계정으로 로그인하면 프로필 줄·설정 창에 **운영자** 버튼이 생깁니다. 운영자는 온라인(Firebase)에서는 Firestore `admins/{uid}` 문서가 있는 계정(콘솔에서 직접 만듦, `docs/firebase-setup.md` 참고), 기기 내 저장소에서는 별명 **`test123`** 입니다.

- 체험 모드에서는 마우스 커서나 손가락(터치)이 곧 내 퍽입니다. 가운데 원에 3초 두면 시작, 결과·모드 선택 화면도 커서 위치로 고르거나 그냥 누르면 됩니다.
- 모드마다 커서 자리에 퍽이 오도록 좌표를 맞춥니다(아케이드는 하단 플레이 존 안으로 제한).
- 기기 내 저장소의 관리자 별명 목록은 `src/account.js` 의 `ADMIN_NICKS`.
- **휴대폰 카메라로 시작 (QR 연결)** (로그인한 회원): 휴대폰은 촬영만 하고, 플레이는 노트북·아이패드 화면을 보면서 합니다. 첫 화면 "카메라 시작" 아래 버튼은 모두에게 보이고, 게스트가 누르면 로그인 안내가 뜹니다(연결 문서를 쓰려면 로그인 필요 — 규칙이 프로필 있는 계정만 받음. 아무나 쓰게 열면 무료 쓰기 한도를 다른 사람이 써 버릴 수 있어서). **휴대폰과 화면 기기가 같은 Wi-Fi 여야** 합니다(버튼 아래·연결 창·휴대폰 페이지에 안내, 연결이 안 되면 상태 줄에도). 버튼을 누르면 QR과 코드 6자리가 뜨고, 휴대폰으로 QR을 찍거나 `…/cam/` 을 열어 코드를 넣은 뒤 **카메라 켜고 연결**을 누르면 됩니다. 영상은 WebRTC로 휴대폰 → 화면 기기에 직접(P2P) 가고, 받은 영상을 내 카메라 자리에 넣으므로 영역·퍽 등록·인식·게임은 카메라 모드와 같습니다(거울 모드 켜짐). 화면 오른쪽 위에 지연 추정(📱 ○○ms, 같은 Wi-Fi에서 보통 50~100ms)이 보입니다. 노트북의 카메라 전환 버튼은 휴대폰 카메라를 바꿉니다. 연결이 끊기면 같은 코드로 자동으로 다시 이어집니다(휴대폰 화면을 켜 둘 것). 연결 중개는 Firestore `rtc/{코드}` 문서 하나(`src/remote-cam.js`) — **`firestore.rules` 의 rtc 규칙이 게시되어 있어야 동작합니다**(main 에 푸시하면 자동 게시, 아래 "규칙 게시"). 같은 Wi-Fi가 아니면(LTE·회사 망) 중계(TURN) 서버가 없어 연결되지 않을 수 있습니다. 휴대폰 페이지: `cam/index.html`, `cam/phone.js`. QR 그리기: `src/vendor/qrcode.mjs` (qrcode-generator 2.0.4, MIT).
- **운영자 화면**: 가입 준비(처음 한 번, 기존 가입자에게 가입 순서대로 번호를 매기고 베타 멤버로 표시), **1회용 코드** 만들기(DM으로 가입 코드를 요청한 게스트·보호자에게 보낼 코드·링크, 코드 복사·링크 복사), **오픈베타 링크** 만들기(마감일·인원 상한, 예: 12월 31일까지 100명), **게스트 안내**(공식 인스타 계정·공개 가입 코드), **베타 기간**(베타 종료일, 회원별 가입 경로(오픈베타 링크·친구 초대·1회용 코드)·의견·상태, 손으로 '정회원 유지'(기한 없음)·'3개월 이용권' 주기·취소), **개발자에게 온 의견** 목록, **의견 추첨 · 3개월 이용권**(종료일 전에 의견을 보낸 회원 중 무작위 30명 → 확인 후 확정하면 당첨자에게 이용권, 당첨자 목록 복사), 코드 목록(오픈베타·1회용만, 사용 횟수, 마감일 바꾸기, 끄기·켜기, 코드·링크 복사), 회원 목록에 로그인 아이디(임시 비밀번호를 아직 안 바꾼 회원 표시), **운영자 비밀번호** 바꾸기(12자 이상, 지금 비밀번호 확인). 로그인 칸은 긴 비밀번호도 받습니다.

## 아케이드 (메인 게임)

웹캠으로 추적한 퍽의 X·Y를 **좌우 테두리 안쪽 × 하단 30% 플레이 존**에 매핑합니다. 화면은 종이색 레인이고, 선은 모두 1px 헤어라인, 퍽은 모두 정원입니다.

- **규칙은 하나**: 작은 **검정 퍽**들이 **같은 속도로, 서로 겹치지 않게** 내려옵니다. **가운데 `코인`이라고 적힌 동전(톱니 테두리의 노란 원, 영어 화면은 `coin`)은 먹고, 검정 퍽은 피합니다.** 빨간 원이 내 퍽입니다. 일부 퍽(쉬움 30%·보통 35%·어려움 40%)은 내 퍽이 있는 줄을 겨냥해 떨어지므로 가만히 있으면 맞습니다.
- **방향** (게임마다 정함, `src/main.js` `depthFlip`):
  - **아케이드**: 아래쪽 플레이 존에서 퍽을 카메라 쪽으로 밀면 화면 위로(퍽들이 내려오는 쪽), 몸쪽으로 당기면 아래로 움직입니다.
  - **흰 화면 게임(퍽 피하기·8자 드리블·자유 연습)**: 판 위쪽이 카메라쪽, 아래쪽이 몸쪽입니다(판 위·아래에 `↑ 카메라쪽 · 밀기` / `↓ 몸쪽 · 당기기` 표시). 퍽을 카메라 쪽으로 밀면 화면 위로, 몸쪽으로 당기면 아래로 움직입니다. 좌우는 영상(거울 모드)과 같습니다.
  - **영역 안에서 배경을 보며 하는 게임(퀵 핸즈·반응 타겟)**: 화면(카메라 영상·영역)은 그대로 두고 **내 퍽의 위아래 움직임만** 영상 속 퍽과 반대로 — 카메라 쪽으로 밀면 영역 안에서 위로 갑니다(`src/render.js` `FLOOR_FLIP_MODES`). 좌우는 그대로입니다.
  - **와이드 드리블**: 카메라 화면 그대로, 내 퍽이 영상 속 진짜 퍽 자리에서 똑같이 움직입니다.
  - 즉 와이드 드리블을 뺀 모든 게임과 모드 선택 화면의 퍽 커서는 카메라 쪽으로 밀면 위로 갑니다. 카메라 위치 때문에 반대로 느껴지면 설정 > "위아래 반대로"를 켜세요(와이드 드리블을 뺀 모든 게임과 모드 선택 커서에 함께 적용). 예전 설정 "카메라 쪽으로 밀면 화면 위로"는 없앴고, 저장돼 있던 값은 버립니다.
- 내려오는 퍽은 모두 화면 위에서 시작합니다. 플레이 존 안에서 갑자기 생기는 방해물은 없습니다.
- **시작**: 등록된 퍽을 가운데 원에 3초 두면 시작(핸즈프리). 시작 버튼으로 시작하면 페이스오프 서클 카운트다운(헤드업 습관 유도).
- **점수** (`src/arcade.js` `SCORE_MULT`): 연속 보너스는 없고, **난이도 배율**만 있습니다 — 같은 플레이라도 **쉬움 ×1 · 보통 ×1.5 · 어려움 ×2**.

  | | 쉬움 | 보통 | 어려움 |
  | --- | --- | --- | --- |
  | **터치**(퍽을 좌우로 치다 방향을 바꾸는 순간, 직전 터치에서 경기장 폭의 8% 이상 움직였을 때만 — 제자리 흔들기 방지) | +1 | +1.5 | +2 |
  | **코인** | +10 | +15 | +20 |
  | **충돌**(0점 아래로는 내려가지 않음) | −3 | −5 | −6 |

  점수는 제한 시간(1·3·5분) 동안 쌓이므로 **대략 1분·쉬움 100점대 ~ 5분·어려움 1,000점 안팎**까지 시간과 난이도에 따라 차등으로 나옵니다(터치는 0.5 단위로 쌓고 화면·랭킹 점수는 반올림한 정수). 랭킹은 시간·난이도별로 따로라 서로 섞이지 않습니다. 예전(충돌 −10, 배율 없음) 아케이드 기록과는 점수 기준이 다릅니다. 나를 겨냥한 퍽을 피해도 점수는 없고 결과의 `피한 퍽` 수로만 남습니다. 즉 **잦은 터치로 퍽을 피하면서 coin을 많이 먹을수록** 점수가 높습니다. 가만히 있으면 점수가 나지 않습니다.
- **연속 터치**: 점수판 옆에 `연속 n`으로 보입니다. 충돌하거나 1.5초 넘게 멈춰 있으면 초기화됩니다. 화면에는 터치마다 방향을 바꾼 자리에 얇은 선만 잠깐 그려지고, 점수 글자는 작게 떠올랐다 사라집니다.
- **난이도**(모드 창 제목 줄에서 선택, 랭킹은 난이도별): 난이도마다 퍽의 개수와 속도가 다릅니다. 한 판 안에서는 속도가 일정하고, 15초마다 퍽이 더 자주 나옵니다.

  | 난이도 | 속도 (화면 폭/초) | 퍽이 나오는 간격 (시작 → 최소) |
  | --- | --- | --- |
  | 쉬움 | 0.18 | 0.65초 → 0.30초 |
  | 보통 | 0.26 | 0.42초 → 0.18초 |
  | 어려움 | 0.36 | 0.20초 → 0.08초 |
- **가림 보정**: 스틱이 퍽을 잠깐 가려 추적이 끊기면 속도로 예측한 위치를 쓰고 그동안 충돌 판정은 하지 않습니다. 영역 안쪽에서 사라진 퍽은 1.5초 동안 마지막 자리에 흐리게 남고(가장자리에서 사라지면 0.4초), 다시 보이면 바로 그 자리로 옮겨 갑니다. 마지막 자리 바로 근처에서는 블레이드에 80~90% 가린 퍽 조각도 퍽으로 받습니다.
- **같은 색 물체에 붙은 퍽 떼어 내기**: 검정 퍽이 검정 스케이트·신발·검정 테이프에 닿으면 색으로는 한 덩어리가 되어 '퍽치고 너무 큼'으로 걸러졌습니다. 이제 예측 자리에 걸친 큰 덩어리 안에서 '퍽 크기 원은 꽉 차고 바로 바깥 고리는 비어 있는 곳'(퍽이 튀어나온 부분)을 찾아 퍽으로 씁니다. 부츠 안쪽은 고리까지 꽉 차서 걸러지고, 퍽을 집어 가면 앞코를 퍽으로 잡지 않습니다. 붙은 채로 이것만으로 1.5초 넘게 이어지면 그만둡니다. 퍽 색과 스케이트 색이 다르면(주황 공 등) 처음부터 헷갈리지 않습니다.
- **스틱으로 잇기 (스틱 색을 지정한 경우)**: 퍽이 블레이드 바로 옆(바닥 폭의 15% 안)에 붙어 있다가 사라지면, 사라지기 직전의 '퍽–블레이드 간격'을 기억해 최대 1.5초 동안 블레이드 자리 + 그 간격을 퍽 자리로 씁니다(`src/occlusion.js`). 블레이드로 퍽을 덮고 끌어도 게임 화면의 퍽이 사라지지 않고 따라오며, 퍽이 다시 보이면 곧바로 진짜 퍽 자리로 돌아갑니다.
  **퍽 색과 테이프 색만 따라갑니다**: 샤프트(스틱 긴 부분) 색이 퍽과 같으면, 퍽이 가려진 순간 퍽처럼 보이는 샤프트 토막(특히 바닥 먼 쪽에 보이는 굵은 윗부분)을 퍽으로 잡아 따라가던 문제가 있었습니다. 이제 인식이 고른 퍽 후보가 '애매한 조각'(가늘고 긴 조각 · 가려져 작아진 조각 · 큰 덩어리에서 떼어 낸 조각, `vision.js` 의 `doubtful`)이고 블레이드 + 간격 자리에서 바닥 폭의 5%(`BRIDGE_TRUST`) 넘게 떨어져 있으면 퍽으로 보지 않고 블레이드로 잇습니다. 빠르게 움직여 번진 퍽은 길쭉한 방향이 움직이는 방향과 같아 애매하다고 보지 않습니다. 테이프 색을 지정하지 않으면 예전과 같습니다.
- **비슷하게 어두운 퍽·스틱 색 나누기 (진한 녹색 퍽 + 검정 스틱 등)**: 예전에는 허용 오차를 바닥과의 색 차이로만 정해(흰 바닥이면 최대 120) 진한 녹색과 검정이 서로의 허용 오차 안에 들어, 검정 스틱 전체가 퍽 색으로도, 퍽 전체가 스틱 색으로도 잡혔습니다. 이제 두 색에 다 맞는 픽셀은 **더 가까운 색 쪽으로만** 봅니다. 색 거리(`colorDist`)는 밝기 차이를 1/4만 세고 색 차이를 그대로 세서, 그늘로 밝기만 바뀐 같은 물체는 가깝고 어두워도 색이 다른 것은 멉니다. 두 색이 거의 같으면(`SEPARATE_MIN` 15 미만: 검정 퍽 + 검정 테이프 등) 나누지 않고, 등록할 때 "퍽과 스틱 색이 거의 같아 서로 헷갈릴 수 있어요"라고 알려 줍니다.
- **등록할 때 붙어 있는 물체 떼어 내기**: 스틱 날이 퍽에 닿은 채로 터치로 지정하거나 원에 두면 둘이 한 덩어리로 잡혀 두 색이 섞이고, 퍽과 스틱이 '둘 다 비슷한 색'으로 등록됐습니다(예: 퍽 rgb(35,58,44), 스틱 rgb(35,51,41)). 이제 누른 자리(원 한가운데) 쪽 색과 색상이 다른 부분이 덩어리의 8% 넘게 붙어 있으면 그 부분을 떼어 내고 잽니다(`separateTouching`). 퍽의 그늘·밝은 윗면, 바닥과 섞인 가장자리, 바닥 그림자는 같은 물체로 봅니다.
- **스틱은 테이프만, 퍽은 퍽만 읽기 (샤프트·그림자는 읽지 않음)**: 퍽과 같은 색(검정) 샤프트와 스틱·날의 그림자가 인식 미리보기에서 빨강(퍽 색)으로, 샤프트 그림에 섞인 테이프 색 점이 초록(스틱)으로 칠해졌습니다.
  - *가늘고 긴 줄 지우기*: 퍽 색이어도 퍽 지름의 0.7배보다 가는 부분이 퍽 지름의 2.5배(`THIN_LONG`) 넘게 이어지면 지웁니다 (열림 연산: 반지름 = 퍽 반지름 × `THIN_RHO` 0.7, 원근대로 줄마다 퍽 크기를 맞춤). 퍽은 그보다 두꺼워 남고, 퍽에 닿은 샤프트는 떨어져 나갑니다. 블레이드에 가려진 퍽 조각처럼 짧은 것은 남깁니다. 샤프트에 섞인 테이프 색 점은 줄을 잇는 데 써서 점에 끊긴 샤프트 토막도 한 줄로 지웁니다(블레이드는 잇지 않음). 퍽을 등록했을 때만.
  - *그림자 거르기*: 그림자는 바닥이 어두워진 것이라 검정 퍽보다 훨씬 밝습니다. 영역을 8×6칸으로 나눠 칸마다 바닥 밝기를 재고, 검정·회색 물체 색이어도 그 자리 바닥 대비 밝기가 물체 자신의 비율에서 바닥 쪽으로 30%(`SHADOW_STEP`) 간 곳보다 밝으면 칠하지 않습니다(흰 판 위 검정 퍽이면 바닥 밝기의 약 35~40%). 사람 그림자처럼 넓은 그림자도 그 자리 바닥 기준이라 그 안의 퍽은 그대로 잡습니다. 색 있는 퍽·테이프는 색으로 이미 갈리고, 바닥이 어두우면(밝기 110 아래) 끕니다. 자동 맞춤도 같은 기준으로 봅니다.
  - *스틱은 블레이드만*: 스틱 색 덩어리 중 고른 것(블레이드 테이프)만 남겨, 미리보기 초록은 테이프뿐입니다.
  - 밝기로 못 가르는 아주 진한 그림자도 줄·날 그림자는 모양으로 지웁니다 (테스트 SH1~SH6).
- **영상 줄이기 잡음 절반**: 카메라 영상(1280×720)을 인식 해상도(240)로 한 번에 줄이면 브라우저가 원본 픽셀 몇 개만 집어 와 잡음이 그대로 남고 얇은 부분이 프레임마다 깜박였습니다. 원본이 인식 폭의 3배 이상이면 두 배 크기로 그린 뒤 2×2 칸씩 평균 내 잡음을 절반으로 줄입니다(1~2ms 더 듦). 화면에 보이는 투명도(배경·내 퍽)는 그림 위에만 덧칠하는 것이라 인식에는 영향이 없습니다. 인식은 항상 카메라 원본 영상을 읽습니다.
- **결과 리포트**: 점수, Coin, 터치, 충돌, 최고 연속 터치, 피한 퍽, 퍽 이동 거리(m), 레벨, 게임 시간

## 헤드업 훈련: 내 퍽 표시 줄이기

화면에서 내 퍽 위치를 보고 움직이면 헤드업이 아니라 "모니터 보고 하기"가 됩니다. 설정의 **내 퍽 투명도 %**(1% 단위)로 플레이 중 화면에 그려지는 내 퍽(본체·궤적)을 흐리게 하거나 없앨 수 있고, 카메라 영상에 비치는 진짜 퍽도 같은 정도로 바닥색으로 덮습니다. 슬라이더 옆 **미리보기**에서 어떻게 보이는지 바로 확인할 수 있고, 슬라이더를 끄는 동안에는 실제 게임 화면에서 그대로 보입니다(카메라에 비친 진짜 퍽을 따라 덮개와 내 퍽이 함께 움직임).

- 0%에서 시작해 익숙해질수록 높이고, 100%에서는 화면에 내 퍽이 전혀 보이지 않아 손의 감각으로만 플레이합니다. 내려오는 퍽·코인·포인트 같은 **목표물은 그대로 보입니다.**
- 모든 게임에 적용됩니다(아케이드, 퍽 피하기, 드릴, 자유 연습 코스).
- 퍽을 등록하거나 원 안에 놓아 시작할 때, 모드·결과 화면에서 고를 때는 항상 또렷이 보입니다.
- 충돌·점수 표시는 그대로 나오므로 결과로 감각을 확인할 수 있습니다. 실제 카메라 영상도 가리려면 **배경 투명도**를 0%로 두세요(영상에 진짜 퍽이 비치지 않게).
- **투명 모드**: 모드 화면의 `투명 모드` 체크를 켜면 내 퍽 표시 %와 상관없이 플레이 중 내 퍽이 전혀 보이지 않습니다. 손의 감각으로만 피하는 별도 도전이라 **랭킹·기록 자랑이 일반과 따로** 집계됩니다(HUD와 결과에 `· 투명` 표시).

## 자유 연습: 나만의 코스 만들기

퍽 피하기처럼 **흰 평면 경기장**에서 직접 코스를 만들어 훈련합니다. 배경은 흰색 고정(배경 투명도 0)이고 **내 퍽 투명도만** 조절합니다.

1. 모드에서 **자유 연습**(8번)을 고르면 경기장 위쪽에 번호 1~10이 나옵니다.
2. 번호를 **끌어다 원하는 곳에 놓으면** 그 자리에 포인트가 생깁니다. 다시 끌어 옮길 수 있고, 위쪽 띠로 되돌리면 지워집니다. "모두 지우기"로 초기화합니다. 코스는 기기에 저장됩니다.
3. **시작**을 누르거나 첫 포인트에 퍽을 2초 두면 시작합니다. 놓은 번호 중 **작은 번호부터 순서대로** 퍽을 드리블해 포인트에 가져다 놓습니다. 다음 포인트는 빨갛게, 지난 포인트는 검게 표시되고 포인트 사이는 선으로 이어집니다.
4. 놓은 포인트를 순서대로 한 번 다 찍으면 **한 사이클**입니다. 사이클이 끝날 때마다 걸린 시간이 표시되고 다시 첫 포인트부터 이어집니다.
5. **목표 사이클 수**는 경기장 위쪽의 `사이클 − 10 +` 로 10부터 100까지 10 단위로 정합니다. 목표를 채우면 자동으로 끝납니다. 중간에 중지해도 그때까지의 기록이 나옵니다.
6. 플레이 중 화면 오른쪽 위에 **완료/목표 사이클**과 **평균·가장 빠른 사이클 시간**이 실시간으로 보이고, 결과 화면에는 완료 사이클, 평균 사이클, 가장 빠른 사이클, 가장 느린 사이클, 통과한 포인트, 총 시간, 이동 거리가 나옵니다. 랭킹에는 오르지 않습니다.

방향은 퍽 피하기와 같습니다: 퍽을 카메라 쪽으로 밀면 화면 위로 움직입니다(플레이 중 경기장 위·아래에 방향 표시). 포인트를 하나도 놓지 않으면 예전처럼 자유 드리블(터치 수·이동 거리)로 동작합니다. 이 모드에서는 가운데 원 대신 코스 화면이 보이므로, 퍽을 새로 등록하려면 보정 > "퍽 다시 등록"을 쓰세요.

## 커뮤니티 (게임 선택 화면의 마지막 칸)

게임 선택 화면 오른쪽 아래의 점선 칸(퍽으로도 고를 수 있음)에서 열립니다. 코스와 기록을 공유하고, 같은 코스로 기록을 겨루는 공간입니다.

- **내 코스 공유**: 자유 연습에서 만든 코스(포인트 배치 + 목표 사이클 수)에 제목과 "이 코스를 연습하면 뭐가 좋아지는지" 설명(200자)을 적어 올립니다. 그 코스를 끝까지 돌아 세운 내 기록(평균·가장 빠른 사이클)이 함께 올라갑니다. `글쓰기` 버튼이나 자유 연습 완주 후 결과 화면의 `코스 공유하기`로 씁니다.
- **이 코스 연습하기**: 글의 버튼을 누르면 그 코스가 자유 연습에 그대로 불려 와 도전이 시작됩니다. 목표 사이클을 완주하면 기록이 그 글의 **기록 게시판(Record board)** 에 자동으로 오릅니다(한 사람당 최고 기록 하나, 평균 사이클 시간이 짧을수록 위, 같으면 가장 빠른 사이클). 기록을 공정하게 비교하려고 포인트를 옮기거나 사이클 수를 바꾸면 도전이 해제됩니다.
- **기록 갱신 자랑**: 1위였던 사람의 기록을 넘어서면 결과 화면에 `신기록!` 과 함께 `기록 갱신 자랑하기` 버튼이 나오고, 누르면 "누구의 기록을 몇 초에서 몇 초로 갈아치웠는지"가 담긴 글이 올라갑니다. 그 글의 `이 코스 연습하기`는 원본 코스 글로 이어져 게시판이 하나로 유지됩니다.
- **기록 자랑**: 아케이드 등 점수 게임을 끝까지 마치면 결과 화면의 `기록 자랑하기`로 점수 글을 올릴 수 있습니다. **모드마다 1개**(모드·시간·투명 여부가 같으면 같은 모드)만 둘 수 있어서, 같은 모드로 다시 자랑하면 새 글이 생기지 않고 기존 글이 새 기록으로 바뀝니다(응원·도전 기록은 그대로, 글쓰기 화면에 미리 안내).
- **나도 연습하기**: 남의 기록 자랑에서 누르면 같은 모드·같은 시간·같은 투명 여부로 바로 맞춰집니다. 누구나 플레이할 수 있지만 **그 글의 도전 기록에는 글쓴이와 나이가 같거나 어린 선수만** 오릅니다(예: 7세의 자랑이면 7세 이하만 등록·갱신, 8세 이상은 연습만). 글쓴이 본인의 플레이도 도전 기록에는 오르지 않습니다(더 높은 점수는 자랑 글을 바꾸면 됨). 결과 화면에 도전 순위나 등록되지 않은 이유가 나옵니다.
- **도전 현황**: 글마다 `도전 n명`, 현재 1위, 나이 제한이 한 줄로 보이고, **글을 누르면 오른쪽에 도전한 사람 수와 상위 5위까지의 이름·기록**이 나옵니다(좁은 화면에서는 그 글 바로 아래). 코스 글은 같은 자리에 코스 기록 게시판 상위 5위가 나옵니다.
- **보기·정렬**: 종류(전체 / 코스 / 기록 자랑), **모드별 보기**(모든 모드 또는 아케이드·퍽 피하기 … 자유 연습 = 코스 글), **최신순 / 응원순**(응원이 많은 글부터).
- 응원(👏, 한 사람당 한 번), 내 글 삭제(두 번 눌러 확인)가 있습니다. 처음에는 바로 연습해 볼 수 있는 **예시 코스 3개**가 들어 있습니다.
- 글쓰기·기록 등록·응원은 **정회원**(로그인)만 할 수 있습니다. 게스트는 읽기와 코스 연습만 됩니다.
- **저장 위치**: 랭킹과 같습니다. Firebase를 연결하기 전에는 글과 기록이 **그 기기에만** 저장되어 같은 기기를 쓰는 선수들끼리만 보입니다. Firebase를 연결하면 온라인으로 바뀌도록 `src/community-firebase.js` 와 `firestore.rules` 규칙을 넣어 두었지만, **실제 Firebase 프로젝트로 검증하지 않은 코드**입니다. 또한 누구나 글을 쓸 수 있는 공개 게시판이 되므로, 온라인으로 열 때는 신고·삭제 같은 운영 수단을 함께 마련하는 것이 좋습니다.

## 언어: 한국어 / English

### 온라인 랭킹 켜기 (Firebase, 무료 요금제로 충분)

1. https://console.firebase.google.com 에서 프로젝트 생성 → **Authentication > 로그인 방법 > 이메일/비밀번호** 사용 설정 (별명이 내부적으로 `u-<hex>@<프로젝트>.firebaseapp.com` 형태의 가상 이메일로 변환됩니다. 예전 `@puck-trainer.app` 계정은 2026-11-17에 모두 새 주소로 옮김).
2. **Firestore Database** 생성(프로덕션 모드) → 규칙 게시: 저장소 시크릿 `FIREBASE_SERVICE_ACCOUNT` 를 한 번 등록하면 main 에 푸시할 때마다 자동 (아래 "규칙 게시"). 등록 전에는 규칙 탭에 `firestore.rules` 내용을 붙여넣고 게시.
3. 프로젝트 설정 > 내 앱 > 웹 앱 추가 → 표시되는 `firebaseConfig` 값을 `src/firebase-config.js` 에 붙여넣고 커밋·푸시.
4. 배포 후 첫 화면 안내문이 "온라인 랭킹"으로 바뀌면 완료. 데이터: `users/{uid}` 프로필(= 정회원), `nicks/{별명}` 고유성, `scores_{모드}/{uid}` 모드별 최고 기록, `posts/{id}` 커뮤니티 글(`records`·`cheers` 하위 컬렉션), `codes/{코드}` 가입 코드(`type`: beta 오픈베타 · one 1회용 · invite 친구 초대 3명), `users/{uid}.invite` 내 초대 코드, `users/{uid}.until`·`coupon` 3개월 이용권 기한, `meta/members` 회원 수(정회원 번호), `config/site` 게스트 안내·베타 종료일, `config/lottery` 의견 추첨 당첨자, `feedback/{uid}` 개발자에게(본인·운영자만 읽음), `admins/{uid}` 운영자.
5. 운영자 계정의 `admins/{uid}` 문서를 콘솔에서 만들고, 운영자 화면에서 **가입 준비**를 한 번 누르면 가입을 받을 수 있습니다.

**보안 규칙이 지키는 것**: 가입(프로필 만들기)은 쓸 수 있는 코드(꺼지지 않음, 마감 전, 횟수 남음)로만, 코드 사용 횟수 +1·회원 번호 +1·별명 등록과 한 번에(트랜잭션) 해야 합니다. 친구 초대 코드는 정회원이 한 번만, 정해진 모양(3명·마감 없음·내 별명)으로만 만들 수 있고 내 프로필의 `invite` 칸과 한 번에 써야 합니다. '정회원 유지'·이용권 기한은 운영자만 바꿉니다. 코드 목록은 운영자만 볼 수 있고(코드를 아는 사람은 그 코드 하나만 확인), 회원 번호·가입 코드·별명은 본인도 못 바꿉니다. 프로필은 본인과 운영자만 읽습니다. 랭킹 기록·글·도전 기록·응원은 정회원만 쓰고, 별명·팀·나이는 내 프로필과 같아야 합니다. 자세한 내용은 아래 "보안 (여러 겹으로)".

> **규칙 게시 (자동)**: main 에 푸시하면 GitHub Actions(`.github/workflows/pages.yml` 의 `rules` 작업)가 저장소의 `firestore.rules` 를 headsuppuck 에 먼저 게시하고, 성공해야 사이트를 배포합니다(새 게임이 새 규칙을 기대하므로). 내용이 같으면 다시 올리지 않습니다. 규칙은 저장소 `firestore.rules` 에서만 고치세요 — 콘솔에서 직접 고친 내용은 다음 배포 때 덮어써집니다. 처음 한 번 저장소 시크릿 `FIREBASE_SERVICE_ACCOUNT`(규칙 게시 전용 서비스 계정 키)를 등록해야 하고, 없으면 경고만 남기고 사이트만 배포합니다. 설정 순서: `docs/firebase-setup.md` 4번. ## 인식 방식 (의존성 없음)

1. 카메라 프레임을 240px 폭으로 축소해 매 프레임 분석합니다.
2. **바닥**: 게임 영역은 사용자가 **네 모서리를 끌어 맞춘 사다리꼴** 하나뿐입니다(시작 준비 1/3 단계, 또는 **영역** 버튼). 예전의 '흰 바닥 자동 감지'와 '카메라 화면 전체'는 없앴고, 예전 설정은 불러올 때 옮깁니다(화면 전체 → 화면 전체 틀, 흰 바닥 자동 → 맞춰 둔 틀이 있으면 그 틀, 없으면 처음 틀). 밝기·채도 기준(설정 > 인식 세부 조정)은 바닥과 구분되지 않는 색을 걸러 내는 데 씁니다.
3. **퍽**: 바닥 안에서 지정 색(기본 검정)의 픽셀을 연결 성분으로 묶고, 크기·원형도·직전 위치와의 거리로 가장 퍽다운 블롭을 고릅니다. 잠시 가려지면 속도로 예측(주황 원)합니다.
4. **스틱**: 보정에서 블레이드/테이프 색을 지정하면 같은 방식으로 추적합니다(마름모 마커).
5. 바닥 사각형 → 단위 정사각형 호모그래피로 게임 좌표를 만들기 때문에, 콘·타겟이 실제 바닥 위에 놓인 것처럼 원근이 적용됩니다.

## 게임 영역을 원근(3D)으로 맞추기

카메라는 비스듬히 바닥을 보기 때문에 실제 직사각형 바닥은 화면에서 **뒤쪽이 좁은 사다리꼴**로 보입니다. 앱은 이 사다리꼴을 평면 좌표로 펴는 호모그래피를 쓰므로, 영역만 정확히 잡으면 뒤쪽에서 조금 움직여도 실제 거리만큼 퍽이 이동한 것으로 계산됩니다.

- **영역** 버튼(키보드 `A`)을 누르면 네 모서리 핸들(뒤·왼쪽, 뒤·오른쪽, 앞·오른쪽, 앞·왼쪽)과 원근 격자가 나타납니다. 맞춰 둔 틀이 있으면 **그대로**(화면 끝에 붙어 있어도) 쓰고, 없으면 화면 가운데 아래쪽의 사다리꼴(뒤쪽 좁게, 앞쪽 넓게)에서 시작합니다. 모서리가 화면 끝에 있어도 손잡이는 화면 안쪽에 보입니다. 핸들을 끌어 실제 바닥 모서리에 맞추고, 격자가 바닥에 붙어 보이면 **완료**를 누르세요. **초기화**는 처음 틀로 되돌립니다.
- 편집 중에는 화면 맨 위 **한 줄 막대**(단계 · 짧은 안내 · 초기화 · 완료)만 보이고 HUD·아래 버튼·인식 칩과 화면 속 글자는 숨겨, 휴대폰에서도 바닥을 가리지 않습니다.
- 아케이드 모드의 좌우 이동과 앞뒤(당기기/밀기)도 이 보정된 바닥 좌표를 쓰므로, 영역을 사다리꼴로 맞추면 뒤쪽에서의 움직임이 작게 보이는 문제가 사라집니다.

### 마커 튐 방지

퍽 위치는 등속 예측(알파-베타) 필터로 부드럽게 따라가며, 예측에서 크게 벗어난 측정값은 1~2프레임 무시하고 3프레임 이상 계속되면 실제 이동으로 받아들입니다. 정지 상태의 미세 떨림은 억제되고, 빠르게 칠 때 모션 블러로 퍽이 길어져도 추적이 끊기지 않도록 면적 허용 범위를 속도에 따라 넓힙니다.

## 아무 바닥·아무 물체로 연습하기

- **가운데 원 하나로 끝**: 대기 중에는 화면 가운데에 항상 원이 있습니다. 퍽이 등록되지 않은 상태에서 물체를 원 안에 놓으면 3초 뒤 그 물체가 퍽으로 등록되고, **등록된 퍽**을 원 안에 두면 3초 뒤 게임이 시작됩니다(핸즈프리). 처음 등록한 퍽과 **다른 물체**를 놓으면 시작하지 않고 "등록된 퍽과 다른 물체입니다"라고 안내하며(등록된 퍽 색 견본 표시), 바꾸려면 화면의 "이 물체로 퍽 교체" 버튼이나 보정 > "퍽 다시 등록"을 누르면 됩니다. 등록된 퍽과 같은 색인데 조명·거리 때문에 추적이 끊긴 경우에는 같은 퍽으로 보고 크기만 다시 익힙니다. 앱이 원 바깥 고리의 배경색과 다른 픽셀 덩어리를 찾아 색·크기를 학습하고, 배경과의 색 차이에 맞춰 허용 오차도 자동으로 정합니다. 공, 병뚜껑, 실제 퍽, 테이프 뭉치 등 **배경과 색만 다르면** 무엇이든 됩니다. 스틱 블레이드도 같은 방법으로 지정합니다.
- 물체가 원보다 크면 "카메라에서 더 멀리"라고 안내하고, 3초 동안 물체가 바뀌거나 움직이면 다시 셉니다. 보정 창에서 연 등록은 화면을 터치하면 취소됩니다(시작 준비 중에는 터치로 취소되지 않음 — 버튼으로).
- **흰 바닥이 없어도 됩니다**: 게임 영역은 네 모서리로 맞추므로 어떤 바닥에서도 됩니다. 노트북 웹캠처럼 화면 전체를 쓰려면 네 모서리를 화면 끝까지 끌어 두세요.
- 같은 색 물체가 배경에 여러 개 있으면 혼동할 수 있으니, 매트와 뚜렷하게 다른 색 하나를 고르세요.

## 인식 자동 맞춤 (집마다 다른 카메라·조명·퍽·바닥)

퍽·스틱을 등록하고 3/3 움직여 보기를 마치면 '인식 세부 조정'의 값이 그 집 영상에 맞춰 자동으로 정해집니다 (`src/autotune.js`, 측정은 `src/vision.js`). 손으로 허용 오차를 다시 만지지 않아도 되게 하려는 것입니다.

- **색 허용 오차 (퍽·스틱 등록 때)**: 두 값 사이에서 고릅니다.
  - *필요한 값(need)*: 등록한 물체 자신이 다 잡히는 값. 물체 안에서도 그늘·반사·가장자리로 색이 퍼져 있어서, 몸통 픽셀의 75%와 한가운데 픽셀의 95%가 잡히는 값(`innerNeed`)을 잽니다.
  - *안전한 값*: 그 값으로 게임 영역을 칠했을 때 바닥·그림자·얼룩이 '퍽만 한 덩어리'(등록 면적의 25%~3배, 스틱은 30% 이상)로 생기지 않고, 영역의 5% 넘게 칠해지지 않는 값 (`distanceMap` + `falseBlobs`). 등록한 물체 자리와 그림자는 빼고 보고, 퍽·스틱 색이 충분히 다르면 추적처럼 더 가까운 쪽 색으로 나눠 봅니다. 스케이트·신발처럼 퍽보다 훨씬 큰 덩어리는 추적이 '너무 큼'으로 거르므로 세지 않습니다.
  - need × 1.35 → 1.2 → 1.1 중 안전한 가장 큰 값 (바닥과의 색 차이 × 0.6 을 넘지 않게). 안 되면 0.95 → 0.85 → 0.75 로 좁혀 보고(퍽이 조금 덜 칠해져도 추적은 됨, `narrow`), 그래도 안 되면 퍽과 거의 같은 색·크기 물체가 영역에 있는 것이라 need 근처로 두고 "치우면 더 정확해요"라고 알립니다(`same`).
  - 예전 기준(바닥과의 색 차이의 절반, 최대 120)은 흰 바닥이면 늘 120이라, 퍽만 한 회색 얼룩·그림자까지 퍽으로 칠했습니다 (테스트 AT2). 지금은 그림자 거르기로 바닥이 어두워진 회색은 허용 오차와 상관없이 칠하지 않고, 자동 맞춤도 그것 때문에 좁히지 않습니다.
- **3/3 움직여 보기 끝**: 네 모서리를 도는 동안 온전히 보인 퍽의 한가운데 색을 모아(`sampleCore`) 95% × 1.1 로 need 를 넓히고(먼 쪽 어두운 모서리·창가 밝은 모서리까지) 허용 오차를 다시 정합니다.
  - **인식 해상도**: 먼 쪽 표적에서 잰 퍽이 영역 배율까지 쳐서 30픽셀 이상 읽히는 가장 가벼운 해상도(240/320/400). 퍽이 크면 400에서 240으로 내리기도 하고, 인식이 24fps 아래로 버거우면 올리지 않습니다 (`chooseProcWidth`).
  - **카메라 프레임(자동일 때)**: 영상 잡음(영역 격자 점의 앞 영상과 밝기 차이 평균, `noiseProbe`)이 3.5 넘고 영역 평균 밝기가 110 아래면 30fps 로 찍습니다(노출이 길어져 잡음이 준다). 이 선택은 저장(`camDark`)되어 다음에 카메라를 켤 때도 30으로 시작하고, 다음 3/3 에서 밝아졌으면 60으로 돌아갑니다.
- 설정 > 인식 세부 조정의 **지금 영상으로 자동 맞추기**: 조명을 바꿨을 때 등, 지금 보이는 퍽(·스틱) 자리를 빼고 허용 오차만 다시 맞춥니다. 슬라이더로 직접 바꾼 값은 그대로 씁니다.
- 테스트: `test/harness.html` 의 AT1~AT9 (색 판정 거리, 얼룩·같은 색 물체·콘크리트 장면, 해상도·잡음·저장).

## 추적 안정성 (이전 프로젝트 리뷰에서 반영한 사항)

- **같은 색 방해물 방지**: 탐색은 바닥 영역 안으로 제한되고, 보정 터치 위치를 추적 시작점으로 사용해 처음부터 다른 물체에 붙지 않습니다. 추적 중에는 예측 위치와 가까운 덩어리를 우선하고, 놓친 뒤 다시 찾을 때는 마지막 퍽과 크기가 비슷한 것만 받습니다. 바닥 밖으로 나간 퍽은 "놓침"으로 처리합니다.
- **강타 대응**: 스틱이 퍽 근처에 있거나 퍽이 빠르게 움직일 때만 탐색 범위를 넓히고 속도로 다음 위치를 예측합니다. 항상 넓히면 방해물에 붙는 부작용이 있어 조건부로만 넓힙니다. **스틱 색을 지정하면 타격 직후에도 퍽을 따라갑니다.**
- **조명 변화**: 주황·파랑처럼 채도가 높은 색은 RGB 대신 정규화 색도로 비교해, 어두워지거나 그림자가 져도 인식이 유지됩니다. 검정 퍽은 RGB 거리로 비교합니다.
- **반사광으로 갈라진 덩어리 병합**, **손상된 저장값 검증**, **카메라 끊김·영상 정지 감지**, **화면 가림 시 안내**를 포함합니다.
- 결과 화면에 **퍽 추적률**이 표시됩니다. 실제 환경에서 이 값과 fps를 보고 슬라이더를 조정하세요.

## 사용 준비

1. 아이패드를 거치대에 세우고 흰 바닥(연습판)이 화면에 크게 들어오게 각도를 맞춥니다. 조명은 고르게, 바닥에 강한 그림자가 없을수록 좋습니다.
2. 앱을 열고 **카메라 시작**(첫 화면 맨 위. 로그인하지 않고 `게스트로 시작`을 눌러도 바로 카메라가 켜짐) → 시작 준비 3단계:
   - **1/3 영역**: 네 모서리를 끌어 바닥에 맞추고 완료(초기화 = 처음 틀). 다음부터는 맞춰 둔 틀을 그대로 씁니다.
   - **2/3 퍽 등록**: 퍽을 가운데 원에 3초. 이미 등록돼 있으면 `등록된 퍽 쓰기`, `영역 다시`로 1/3로 돌아갈 수 있습니다.
   - **3/3 움직여 보기**: 바닥 네 모서리의 표적에 퍽을 가져가 4개 모두 닿으면(끝까지 잘 잡히는지 확인) 바로 모드 창이 열립니다(게임은 저절로 시작하지 않음 — 퍽을 가운데 칸에 둔 뒤 카드에 2초, 또는 터치로 고름). 퍽이 안 보이면 안내가 나오고, `퍽 다시`·`영역 다시`·`건너뛰기` 버튼이 있습니다.
   - 모드 창에서 게임·시간(1·3·5분)·난이도를 고릅니다. 준비 단계마다 안내는 화면 맨 위 한 줄뿐이고, `Esc`는 지금 단계를 건너뜁니다.
3. **보정** → "퍽 터치로 지정" 후 화면 속 퍽을 터치합니다(검정 퍽은 기본값으로도 동작). 스틱은 블레이드에 **주황·파랑 등 눈에 띄는 색 테이프**를 감고 같은 방법으로 지정하세요. 흰색·검정 테이프는 바닥/퍽과 구분되지 않습니다.
   - 지정하는 동안은 어느 게임에서든(아케이드·퍽 피하기·8자처럼 배경이 흰 화면인 게임 포함) 게임 화면 대신 카메라 영상이 보이고, 진행 중이던 게임은 멈춥니다. `Esc`로 취소.
   - 누른 자리 근처(화면 폭의 약 5%)에서 주변 바닥과 색이 다른 물체로 붙으므로 작은 퍽을 조금 빗나가게 눌러도 됩니다. 색은 바닥과 섞인 가장자리가 아니라 물체 한가운데 색, 허용 오차는 주변 바닥과의 색 차이로 정합니다(원 안에 3초 자동 지정과 같은 기준).
   - 가운데 원 자동 지정의 배경색은 원 바깥 고리의 **중앙값**(게임 영역 안쪽만)으로 잽니다. 다리·스틱이 고리를 반쯤 가리거나 영역 밖 벽이 고리에 걸려도 바닥색이 틀어지지 않아 퍽을 놓치지 않습니다.
   - 퍽이 처리 해상도에서 20px보다 작게 보이면(멀리 둔 카메라·작은 공) 등록할 때 **인식 해상도를 400으로 자동으로 올립니다**.
   - 가운데 원(퍽 등록·핸즈프리 시작)은 화면이 아니라 **퍽 크기 기준으로 지름이 퍽의 약 2배**입니다. 등록된 퍽이 있으면 그 크기로, 없으면 지정한 영역 한가운데의 폭 × (퍽 지름 7.6cm ÷ 설정의 영역 실제 폭)으로 추정합니다. 놓기 어려울 만큼 작아지지 않게 최소 크기(화면 짧은 변의 3%)가 있고, 예전 크기(9.5%)보다 커지지 않습니다. 스틱 테이프 등록 원은 블레이드가 길어 예전 크기 그대로입니다.
4. 설정 > **인식 세부 조정**을 펼치면 인식 미리보기(퍽 = 빨강, 스틱 = 초록, 퍽으로 고른 자리 = 동그라미)를 보며 퍽·스틱 색 허용 오차와 인식 해상도를 조정할 수 있습니다. 미리보기는 설정 창 안에만 있어 게임 화면을 가리지 않습니다(개발용 `D` 키 마스크도 게임 중에는 숨김). 허용 오차는 퍽·스틱을 등록할 때 자동으로 맞춰지므로 보통은 건드리지 않아도 됩니다. 예전의 '바닥 밝기 기준·바닥 채도 허용'은 흰 바닥 자동 감지용이라, 영역을 네 모서리로 정하는 지금은 인식에 쓰이지 않아 설정에서 뺐습니다. 모드 창 오른쪽 위의 `설정` 버튼으로도 열 수 있습니다(닫으면 모드 창으로 돌아옴). 그 왼쪽의 **`퍽·스틱 등록`** 은 보정 창을 모드 창 위에 열고, 원 안에 3초·터치로 지정이 끝나면(등록했든 취소했든) 모드 창으로 바로 돌아옵니다 — 모드 창을 닫고 보정한 뒤 다시 여는 단계가 없습니다.
5. **카메라를 가로 <-> 세로로 돌리면**(휴대폰 카메라·아이패드): 화면이 새 방향에 맞춰 바뀌고, 등록한 퍽·스틱 크기를 새 방향으로 환산합니다(같은 퍽이 가로에서는 처리 화면에서 약 1/3 면적으로 보이므로 다시 등록하지 않아도 됨). 게임 영역(네 모서리)은 화면 비율 기준이라 돌리기 전 자리에 남으므로, 게임을 멈추고 **영역 편집만** 바로 엽니다(퍽 등록·움직여 보기는 다시 하지 않음, 저장하면 하던 모드 창으로). 연결 속도 때문에 해상도만 바뀌는 경우(비율 그대로)는 아무것도 바꾸지 않습니다. 휴대폰의 화면 회전 잠금이 켜져 있으면 영상이 옆으로 누워서 오므로 꺼 두세요(휴대폰 페이지 안내). `src/main.js` `onOrientationFlip`.
6. **모드** 선택 후 **시작**.

## 휴대폰을 거치대에 세워 플레이

### 방법 A. 컴퓨터를 서버로 (같은 Wi-Fi)

1. 컴퓨터에서 프로젝트 폴더를 열고 `python3 serve.py` (Windows는 `python serve.py`)를 실행합니다.
2. 터미널에 **휴대폰에서 열 주소가 숫자 IP로** 표시됩니다. 예: `https://192.168.0.12:8443`. `<컴퓨터IP>` 같은 글자가 아니라 이 숫자 주소를 휴대폰 브라우저에 그대로 입력하세요. (`pip install qrcode` 를 설치해 두면 QR 코드도 표시됩니다.)
3. 인증서 경고가 뜨면 iPhone Safari는 "세부사항 보기 > 이 웹 사이트 방문", Android Chrome은 "고급 > 이동"으로 계속합니다.
4. 안 열리면 순서대로 확인: 휴대폰과 컴퓨터가 같은 Wi-Fi인지(휴대폰 데이터 끄기) → 처음 실행 시 뜨는 방화벽 팝업에서 Python 허용(개인 네트워크) → 공유기의 "AP 격리/기기 간 통신 차단" 해제 → 포트 변경(`python3 serve.py 9443`).

### 방법 B. GitHub Pages 링크로 바로 열기 (컴퓨터 없이, 추천)

`main` 브랜치에 푸시하면 `.github/workflows/pages.yml` 이 자동 배포하고, 공식 주소 **https://puck-trainer.com/** 으로 열립니다. GitHub 기본 주소 `https://ochodoit.github.io/puck-dribble-trainer/` 로 들어와도 새 주소로 넘어갑니다(예전 주소 `/semple/` 은 없어짐).

- 배포 실패 `No artifacts named "github-pages"`: GitHub 쪽에서 올린 직후 아티팩트가 늦게 보여 가끔 생깁니다. 워크플로가 같은 작업 안에서 10초·30초·60초 기다렸다 다시 시도합니다. 그래도 실패하면 **Re-run 대신** Actions › Deploy to GitHub Pages › **Run workflow** 로 새로 돌리세요(Re-run 하면 아티팩트가 두 개라 또 실패).

- Hosting.kr DNS 레코드: `A @` 185.199.108.153 / 185.199.109.153 / 185.199.110.153 / 185.199.111.153, `CNAME www` → `ochodoit.github.io`, `TXT _github-pages-challenge-ochodoit` (소유 확인 값, 지우지 말 것) 워크플로가 Pages를 자동 활성화하지 못하면 저장소 **Settings > Pages > Source**를 `GitHub Actions`로 한 번만 바꿔 주세요. HTTPS라 휴대폰 카메라가 바로 허용되고 인증서 경고도 없습니다.

예전의 접속 코드(PIN) 화면은 없앴습니다. 누구나 게스트로 플레이할 수 있고, 랭킹·글쓰기는 가입 코드로 가입한 정회원만 합니다(위 "정회원 · 가입 코드 · 랭킹").

### 플레이 설정

1. (방법 A의 경우) 같은 Wi-Fi의 컴퓨터에서 `python3 serve.py` 를 실행하고, 휴대폰 브라우저에서 터미널에 표시된 주소를 엽니다.
2. 홈 화면에 추가하면 주소창 없이 전체화면으로 실행됩니다. 세로·가로 모두 지원합니다.
3. 거치대에 세우고 **전면 카메라**(기본)로 자신과 연습 공간이 보이게 둡니다. 화면이 거울처럼 보이며, 🔄 버튼으로 후면 카메라로 바꿀 수 있습니다(후면은 거울 모드 자동 해제).
4. 게임 영역은 시작 준비 1/3에서 네 모서리로 맞춥니다(나중에 바꾸려면 **영역** 버튼). 휴대폰을 **가로로** 두면 화면이 넓어집니다(세로일 때 작은 안내 띠). 휴대폰 화면을 TV에 미러링해도 되며, 높이가 낮은 가로 화면(최대 520px)에서는 창·버튼이 촘촘하게 배치됩니다.
5. **핸즈프리 시작**: 멀리 떨어져 있어도 퍽을 가운데 초록 원 안에 3초 두면 게임이 시작되고, 게임이 끝난 뒤에도 같은 방법으로 다시 시작됩니다(설정에서 끌 수 있음). 아케이드 모드는 이 경우 카운트다운을 생략하고 바로 GO 합니다.
6. 플레이 중 화면이 꺼지지 않도록 Wake Lock을 요청합니다(저전력 모드에서는 거부될 수 있으니 자동 잠금을 길게 설정하세요).
7. 세로 화면에서는 장애물 낙하 속도를 화면 비율에 맞게 보정해 가로와 같은 체감 속도를 유지합니다.

## 카메라가 연결되지 않을 때

"카메라 시작"이 실패하면 첫 화면에 오류 이름과 해결 순서, 감지된 카메라 목록이 표시됩니다. 자주 있는 원인:

| 증상 | 해결 |
| --- | --- |
| 권한 거부 (NotAllowedError) | Chrome/Edge: 주소창 왼쪽 자물쇠 아이콘 > 카메라 "허용" > 새로고침. Windows: 설정 > 개인 정보 및 보안 > 카메라 > "카메라 액세스"와 "앱이 카메라에 액세스하도록 허용" 켜기. macOS: 시스템 설정 > 개인정보 보호 및 보안 > 카메라 > 브라우저 켜기 |
| 열 수 없음 / 응답 없음 (NotReadableError, TimeoutError) | Zoom·Teams·카카오톡·카메라 앱·OBS 등 카메라를 쓰는 프로그램을 트레이까지 완전히 종료, 다른 탭 확인, 브라우저 재시작 |
| 카메라 없음 (NotFoundError) | 노트북 카메라 가림막·Fn 카메라 끄기 키 확인, 장치 관리자에서 카메라 사용 여부 확인 |
| 선택한 카메라 사용 불가 (OverconstrainedError) | 목록에서 다른 카메라 선택 후 "다시 시도" (IR/적외선 카메라는 피하세요) |

"진단 정보 복사" 버튼으로 복사한 내용을 전달하면 원인을 빠르게 찾을 수 있습니다.

## 노트북 웹캠으로 플레이

노트북 카메라는 바닥을 내려다보지 않고 정면을 보기 때문에 설정 몇 가지를 바꾸면 잘 동작합니다.

1. 노트북을 의자·상자 위에 올려 카메라를 70cm 이상 높이에 두고, 화면을 뒤로 젖혀 연습 공간이 화면 아래쪽 2/3를 차지하게 합니다. 거울 모드(기본 켜짐)라 화면이 거울처럼 보입니다.
   - **카메라 높이 시험** (실제 크기 3D 장면: 2m×1.5m 연습판, 지름 7.6cm 퍽, 화각 66°, 영역이 화면에 꽉 차게): 2.2m 평균 위치 오차 1.2cm · 1.6m 2.1cm · 1.2m 3.4cm · 80cm 5.6cm(모두 25/25 추적) · 50cm 21/25(먼 줄을 놓침) · 25cm(바닥에 둠) 추적 실패. 원근 보정은 모든 높이에서 맞고, 낮을수록 먼 쪽 바닥이 납작해져 퍽이 몇 픽셀로 작아지고 퍽 두께 때문에 위치가 밀립니다. 그래서 안내는 **1~1.5m, 최소 80cm, 영역이 화면 세로의 1/3 이상**입니다(테스트 CAM).
   - **TV 옆** (같은 시험, 옆으로 비스듬히): 1.2m 높이에서 옆으로 0.6m(18°) 3.6cm · 1m(31°) 3.6cm · 1.5m(46°) 3.8cm — 네 모서리만 맞추면 정면(3.5cm)과 거의 같습니다. **TV 위 가운데**(1.6m)는 2.2cm.
   - **카메라 위치 점검** (`src/placement.js`): 시작 준비 3/3 움직여 보기에서 네 모서리 표적에 닿을 때의 퍽 크기와 먼 쪽 절반에서 놓친 비율을 재고, 영역 가운데의 바닥→화면 국소 변환의 두 특이값 비로 내려다보는 각도를 어림해(영역 깊이/폭 0.75 가정, 옆에서 찍어도 맞음) '더 높이 / 지금이 최소 / 좋아요 / 조금 낮춰도 돼요'를 모드 창 위 안내로 알려 줍니다. 건너뛰기를 눌러도 영역 모양만으로 너무 낮아 보이면 알려 줍니다. 기준값은 위 시험(정면·TV 옆 13가지)에서 정했습니다(테스트 PLC).
2. **게임 영역**: 시작 준비 1/3(또는 **영역** 버튼)에서 네 모서리를 연습 공간에 맞추세요. 화면 전체를 쓰려면 네 모서리를 화면 끝까지 끌어 두면 됩니다.
3. **설정 > 인식 세부 조정 > 인식 해상도**: 웹캠에서 퍽이 작게 보이면 `높음(320)` 또는 `최고(400)`으로 올리세요. 처리 시간은 240px 기준 약 2ms라 여유가 있습니다.
4. **보정**: 어두운 바닥에서는 검정 퍽이 안 보이므로 주황 볼이나 밝은 색 연습용 퍽을 쓰고 화면에서 클릭해 색을 지정하세요. 스틱 블레이드에는 다른 색 테이프를 감고 지정하세요.
5. **설정 > 조작 대상**: 퍽이 없으면 `스틱 블레이드`로 바꿔 블레이드만으로 아케이드와 드릴을 할 수 있습니다.
6. 실행은 아래처럼 localhost로 열면 HTTPS 없이도 카메라가 허용됩니다(Chrome, Edge, Safari).

```bash
python3 serve.py --http        # macOS/Linux
python serve.py --http         # Windows
# -> http://localhost:8080
```

조작은 마우스 클릭과 키보드(`Space` 시작·중지, `F` 전체화면 등) 모두 됩니다. 창을 최소화하거나 다른 창으로 완전히 가리면 브라우저가 프레임 처리를 멈추므로 전체화면(`F`)을 권장합니다.

## 운영 비용 · 유료 전환 기준 (2026-11-18 기준)

Firebase는 서버를 직접 두는 방식이 아니라(서버리스) 이용자가 늘어도 **서버를 늘릴 일은 없습니다**. Google이 알아서 늘려 주고, 따질 것은 **하루 무료량**과 **요금제**뿐입니다.

| 항목 | 무료(Spark) 한도 | 이 게임에서 쓰는 양 |
|---|---|---|
| Firestore 읽기 | 하루 5만 건 (태평양 시간 자정, 한국 오후 4~5시에 초기화) | 순위를 개수 세기(count) 쿼리로 세서(2026-11-18) 회원 게임 한 판 끝 **약 5건**(예전 최대 약 600건), 게스트 결과 2건, 랭킹 화면 최대 약 100건(1분 동안 다시 안 읽음), 내 정보 약 24건 + 기록 있는 게임마다 4건 |
| Firestore 쓰기 | 하루 2만 건 | 게임 한 판에 2~3건 — 넉넉함 |
| 저장 용량 | 1 GiB | 회원 1만 명이어도 수십 MB |
| 로그인(Authentication) | 이메일/비밀번호 로그인은 일반 이용에 한도 걱정 없음 (Identity Platform으로 올리면 Spark 하루 3,000명) | 가입은 IP당 시간당 100건 |
| 사이트(GitHub Pages) | 월 대역폭 약 100 GB(권장) | 파일이 작아 수만 명까지 괜찮음 |

- **예전 코드**: 게임 기록이 300개 넘게 쌓이면 하루 회원 게임 약 80판(읽기 5만 ÷ 600)에서 무료 읽기가 바닥났습니다(Spark는 돈이 나가지 않고 그날만 막힘).
- **지금(count 쿼리)**: 순위 한 번에 읽기 1건(일치하는 기록 1,000개당 1건). 회원 한 명이 하루 10판 하고 랭킹·내 정보를 한 번씩 보면 약 250건이라 **하루 활동 회원 약 200명**까지 무료 안에 들어옵니다(랭킹 화면을 덜 보면 더 많이).
  - 연령대·국가·팀 안의 순위는 기록 문서의 **순위 색인 칸**(`ags`·`cts`·`tms` = '묶음|10자리 점수', `src/account.js` `rankIdx`)의 범위로 셉니다. 칸 하나의 범위라 Firestore 기본 색인만 쓰고 **복합 색인을 만들 필요가 없습니다**. 규칙(`rankIdxOk`)이 칸 값이 점수·묶음과 맞는지 확인합니다.
  - 색인 칸이 생기기 전의 기록은 주인이 다음에 그 게임을 하거나 내 정보를 열 때 채워지고, 그 전까지는 연령대·국가·팀 순위에서 빠집니다(전체 순위에는 들어감).
  - 같은 점수는 같은 순위입니다(1, 2, 2, 4).
- **Blaze(종량제)로 바꿀 때**: ① 구독 결제를 붙일 때(결제 웹훅·지급 처리에 Cloud Functions가 필요하고, Functions는 Blaze 전용) ② 최적화 후에도 하루 무료량을 자주 넘길 때. Blaze도 같은 무료량이 먼저 적용되고 넘은 만큼만 냅니다(읽기 10만 건에 몇십 원 수준, 지역별 정확한 값은 Google Cloud 가격 페이지). 바꿀 때는 **예산 알림**(예: 월 1만 원)을 꼭 걸기.
- **구독형으로 갈 때 사이트**: GitHub Pages 이용 약관은 상업용 서비스(SaaS) 운영을 주목적으로 쓰지 말라고 되어 있어, 유료 구독을 시작하면 Firebase Hosting이나 Cloudflare Pages로 옮기는 것을 검토.

## 보안 (여러 겹으로)

한 겹이 뚫려도 다음 겹이 막도록 나눠 두었습니다. 서버 코드 없이(GitHub Pages + Firebase 무료 요금제) 할 수 있는 만큼입니다.

| 겹 | 막는 것 | 어디서 |
| --- | --- | --- |
| 1. 보안 규칙 | 남의 프로필(나이·가입 코드) 읽기, 정해지지 않은 칸 쓰기(예: 스스로 '정회원 유지'), 남의 별명·팀·나이로 기록·글 올리기(사칭), 운영자처럼 보이는 별명(운영자·관리자·admin·official·퍽 트레이너), 최고 기록 낮추기, 2초 안에 연달아 기록 쓰기, 공식 글 흉내 | `firestore.rules` |
| 2. 화면 코드 | 글·기록의 숫자 칸을 화면에 넣기 전에 숫자로 고정(조작된 문서로 HTML이 끼어들지 못함), 글자는 모두 이스케이프 | `src/main.js`, `src/community-ui.js` |
| 3. 브라우저 정책 (CSP) | 혹시 HTML이 끼어들어도 이 사이트·Firebase·Google 애널리틱스(googletagmanager.com) 외의 스크립트는 실행되지 않음, 플러그인(object) 금지 | `index.html` 의 `Content-Security-Policy` |
| 4. 공식 주소에서만 실행 | 다른 주소에 복사해 올린 사이트, 다른 사이트의 틀(iframe) 안에 넣어 띄우기(클릭 가로채기) | `src/guard.js` |
| 5. 계정 | 새 계정의 로그인용 가상 이메일은 이 프로젝트의 Firebase 도메인(아무도 메일을 받을 수 없음)이라 비밀번호 재설정 메일로 계정을 뺏을 수 없음. 운영자는 12자 이상 비밀번호(운영자 화면에서 바꾸기). 비밀번호를 잊은 회원은 운영자가 서버 도구(서비스 계정 키, 운영자 PC에만)로 임시 비밀번호를 주고, 그 계정은 새 비밀번호를 정하기 전에는 들어갈 수 없음. 디버그 훅(`__puckTrainer`)은 내 컴퓨터에서만 | `src/account-firebase.js`, `src/main.js` |
| 6. 정리 | 운영자는 글·도전 기록·랭킹 기록·의견을 지울 수 있음. 카메라 없이 체험한 기록은 랭킹·출석·자랑에 안 올라감 | 규칙 + 운영자 |

알아 둘 한계와 추가로 할 수 있는 것:
- **예전 계정**(`u-…@puck-trainer.app`)은 2026-11-17에 모두 새 주소로 옮겨서 남은 계정이 없습니다. 누가 `puck-trainer.app` 도메인을 사도 계정을 뺏을 수 없으니 사 둘 필요가 없습니다. 예전 주소 계정이 다시 생기면(옛 백업 복원 등) 앱이 로그인할 때 새 주소로 옮기는데, Firebase의 이메일 열거 보호가 켜져 있으면 막히므로 Authentication > 설정 > 사용자 작업 > **이메일 열거 보호**를 잠깐 끄고, 그 계정으로 한 번 로그인한 뒤 다시 켜세요. 운영자 계정은 비밀번호를 12자 이상으로 바꾸세요.
- 서버 없이 점수를 계산하므로, 마음먹고 조작하는 사람의 가짜 점수를 완전히 막을 수는 없습니다(범위·내림 금지·속도 제한으로 어렵게만 함). 이상한 기록은 운영자가 지웁니다.
- 일반 회원은 아이디 + 8자 이상 비밀번호(영문+숫자)입니다. 아이디는 공개되지 않아 남이 별명만 보고 로그인을 시도할 수 없습니다. Firebase가 틀린 시도를 자동으로 늦추고, 아래 App Check를 켜면 더 안전합니다. 예전 계정이 아이디를 만들 때 로그인 주소도 아이디 주소로 바꾸려면 이메일 열거 보호를 끈 동안이어야 합니다(켜져 있으면 예전 주소가 그대로 남고, 앱은 `ids/{아이디}` 에 적힌 주소로 로그인).
- 콘솔에서 더 켤 수 있는 겹(선택): **API 키 HTTP 리퍼러 제한**(Google Cloud 콘솔 > API 및 서비스 > 사용자 인증 정보 > 브라우저 키 > `https://puck-trainer.com/*`, `https://ochodoit.github.io/*`, `http://localhost/*`, `http://127.0.0.1/*`), **App Check**(reCAPTCHA v3, 복사한 사이트·스크립트의 Firebase 접근 차단).
