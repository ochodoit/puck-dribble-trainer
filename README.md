# 🏒 퍽 드리블 트레이너

아이패드 카메라로 **흰 바닥(연습판)·스틱·퍽을 실시간 인식**해 화면에 겹쳐 보여주고,
장애물 피하기와 스틱핸들링 트레이닝을 진행하는 웹 앱입니다. 프레임워크·외부 라이브러리 없이
순수 HTML/CSS/JS(ES Modules)로 만들어졌고, 홈 화면에 추가하면 전체화면 앱처럼 동작합니다(PWA).

## 디자인

미니멀·타이포그래피 중심. 종이색 바탕 + 잉크 블랙 + **포인트 레드 한 색**으로 통일했습니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| Paper | `#F4F1EA` | 바탕, 카드, 플레이 중 영상 위 워시 |
| Ink | `#161616` | 글자, 얇은 선(1.5px), 장애물 도형 |
| Red (PANTONE 179 C) | `#E03C31` | 포인트: 플레이어의 퍽, 시작 버튼, 필기체 악센트, 경고 |
| Yellow (PANTONE 123 C) | `#FFC72C` | 수집 아이템(황금 퍽) 전용 |

- 글꼴: 제목·숫자는 굵은 세리프(Fraunces / Noto Serif KR), 본문은 Poppins / Noto Sans KR, 악센트는 필기체(Caveat / Nanum Pen Script, 항상 레드). Google Fonts에서 불러오며, 오프라인이면 시스템 글꼴로 대체됩니다.
- 버튼·라벨은 알약형 테두리, 이모지 대신 번호(01–07)와 타이포로 구분합니다.
- 캔버스(게임 화면)도 같은 토큰을 씁니다: `src/theme.js` ↔ `style.css :root`. 색을 바꾸려면 두 곳의 값을 함께 바꾸세요.
- 플레이 중에는 영상 채도를 낮추고 하단 버튼을 걷어 화면을 비웁니다(우하단 "중지"만 남김).
- **배경 투명도**: 설정의 "배경 투명도 %" 슬라이더로 아케이드·퍽 피하기에서 카메라 영상이 비치는 정도를 정합니다. 0%는 종이색으로 완전히 덮고, 100%는 영상이 그대로 보입니다(기본 12%).

## 게임 규칙: 시간과 점수

- **제한 시간 동안의 점수로 겨룹니다.** 기본 1분, 모드 화면에서 3분·5분으로 바꿀 수 있습니다(아케이드·퍽 피하기에 적용. 드릴은 고유 시간).
- **목숨은 없습니다.** 충돌하면 감점(아케이드 −100, 퍽 피하기 −50)되고 콤보가 초기화되며 잠깐 무적이 됩니다. 시간이 끝날 때까지 계속 플레이합니다.
- **랭킹은 시간별로 따로** 집계됩니다(아케이드 1분, 아케이드 3분 … 은 서로 다른 순위표).
- 퍽 추적을 0.6초 넘게 놓치면 게임과 시계가 함께 멈추고, 다시 보이면 이어집니다.
- **게임이 끝나면** 결과 화면에서 퍽 위치로 고릅니다. 퍽을 **왼쪽 영역에 2초** 두면 한 번 더, **오른쪽 영역에 2초** 두면 모드 선택으로 갑니다. 결과 창 안의 트랙에 퍽의 좌우 위치가 빨간 점으로 보이고, 선택지가 채워지며 실행됩니다. 가운데에 두면 아무 일도 일어나지 않고, 화면을 눌러도 됩니다(핸즈프리 설정을 끄면 터치만).
- **모드 선택 화면은 3×3 배치**입니다. 1~4번과 6~8번에 게임 7개, 가운데 5번은 퍽이 대기하는 자리라 비워 두었고, 9번은 **커뮤니티**입니다(아래 참고).
- **모드 선택 화면도 퍽으로** 고릅니다. 퍽의 좌우·앞뒤 위치가 카드 목록 위의 빨간 커서가 되고, 카드 위에 2초 머물면 그 모드가 선택됩니다(카드 아래에 진행 띠 표시). 화면이 열릴 때 커서가 올라가 있던 카드는 한 번 벗어났다가 다시 와야 선택됩니다. 게임 시간(1·3·5분)과 2인 대결은 터치로 바꿉니다.

## 테스트 관리자: 마우스 모드

카메라 없이 개발·점검할 때 씁니다. 별명 **`test123`** 으로 로그인하면 첫 화면의 "카메라 시작" 아래에 **마우스로 시작 (카메라 없이)** 버튼이 생깁니다.

- 마우스 커서(터치도 가능)가 곧 내 퍽입니다. 가운데 원에 3초 두면 시작, 결과·모드 선택 화면도 커서 위치로 고르거나 그냥 클릭하면 됩니다.
- 모드마다 커서 자리에 퍽이 오도록 좌표를 맞춥니다(아케이드는 하단 플레이 존 안으로 제한).
- 관리자 별명 목록은 `src/account.js` 의 `ADMIN_NICKS`. 별명은 한 사람만 가입할 수 있으므로 먼저 가입한 사람이 관리자가 됩니다.

## 아케이드 (메인 게임)

웹캠으로 추적한 퍽의 X·Y를 **좌우 테두리 안쪽 × 하단 30% 플레이 존**에 매핑합니다. 화면은 종이색 레인이고, 선은 모두 1px 헤어라인, 퍽은 모두 정원입니다.

- **규칙은 하나**: 색이 다른 작은 퍽들이 무작위 위치에서 **같은 속도로, 서로 겹치지 않게** 내려옵니다. **가운데 `coin`이라고 적힌 동전(톱니 테두리의 노란 원)은 먹고, 나머지 색(블랙·블루·그린·바이올렛)은 피합니다.** 빨간 원이 내 퍽입니다.
- **방향**: 퍽을 카메라 쪽으로 밀면 화면 위로(퍽들이 내려오는 쪽), 몸쪽으로 당기면 아래로 움직입니다. 카메라 위치 때문에 반대로 느껴지면 설정 > "아케이드: 카메라 쪽으로 밀면 위로"를 끄세요.
- 내려오는 퍽은 모두 화면 위에서 시작합니다. 플레이 존 안에서 갑자기 생기는 방해물은 없습니다.
- **시작**: 등록된 퍽을 가운데 원에 3초 두면 시작(핸즈프리). 시작 버튼으로 시작하면 페이스오프 서클 카운트다운(헤드업 습관 유도).
- **점수**: 1초마다 +10, 가까이 스쳐 피한 퍽 +50, 아슬아슬 회피 **Deke +100**(히트박스 바깥 15% 스침), coin +200, 충돌 −100. 멀리서 그냥 지나간 퍽은 점수가 없습니다.
- **콤보 배율**: 피하거나 먹을 때마다 콤보 +1. 5콤보 ×1.5, 10콤보 ×2, 20콤보 **Fever ×3 + 보너스 300**. 충돌 시 초기화
- **난이도**: 난이도마다 퍽의 개수와 속도가 다릅니다. 한 판 안에서는 속도가 일정하고, 1,000점마다 퍽이 더 자주 나옵니다.

  | 난이도 | 속도 (화면 폭/초) | 퍽이 나오는 간격 (시작 → 최소) |
  | --- | --- | --- |
  | 쉬움 | 0.18 | 1.30초 → 0.60초 |
  | 보통 | 0.26 | 0.85초 → 0.36초 |
  | 어려움 | 0.36 | 0.40초 → 0.16초 |
- **가림 보정**: 스틱이 퍽을 잠깐 가려 추적이 끊기면 속도로 예측한 위치를 쓰고 그동안 충돌 판정은 하지 않습니다.
- **결과 리포트**: 점수, 최고 콤보, Deke 횟수, 피한 퍽, Coin, 충돌, 퍽 이동 거리(m), 레벨, 게임 시간

## 헤드업 훈련: 내 퍽 표시 줄이기

화면에서 내 퍽 위치를 보고 움직이면 헤드업이 아니라 "모니터 보고 하기"가 됩니다. 설정의 **내 퍽 표시 %** 로 플레이 중 화면에 그려지는 내 퍽(본체·고리·궤적)을 흐리게 하거나 없앨 수 있습니다.

- 100%에서 시작해 익숙해질수록 10%씩 낮추고, 0%에서는 화면에 내 퍽이 전혀 보이지 않아 손의 감각으로만 플레이합니다. 내려오는 퍽·coin·포인트 같은 **목표물은 그대로 보입니다.**
- 모든 게임에 적용됩니다(아케이드, 퍽 피하기, 드릴, 자유 연습 코스).
- 퍽을 등록하거나 원 안에 놓아 시작할 때, 모드·결과 화면에서 고를 때는 항상 또렷이 보입니다.
- 충돌·점수 표시는 그대로 나오므로 결과로 감각을 확인할 수 있습니다. 실제 카메라 영상도 가리려면 **배경 투명도**를 0%로 두세요(영상에 진짜 퍽이 비치지 않게).

## 자유 연습: 나만의 코스 만들기

평면 경기장에서 직접 코스를 만들어 훈련합니다.

1. 모드에서 **자유 연습**(8번)을 고르면 경기장 위쪽에 번호 1~10이 나옵니다.
2. 번호를 **끌어다 원하는 곳에 놓으면** 그 자리에 포인트가 생깁니다. 다시 끌어 옮길 수 있고, 위쪽 띠로 되돌리면 지워집니다. "모두 지우기"로 초기화합니다. 코스는 기기에 저장됩니다.
3. **시작**을 누르거나 첫 포인트에 퍽을 2초 두면 시작합니다. 놓은 번호 중 **작은 번호부터 순서대로** 퍽을 드리블해 포인트에 가져다 놓습니다. 다음 포인트는 빨갛게, 지난 포인트는 검게 표시되고 포인트 사이는 선으로 이어집니다.
4. 놓은 포인트를 순서대로 한 번 다 찍으면 **한 사이클**입니다. 사이클이 끝날 때마다 걸린 시간이 표시되고 다시 첫 포인트부터 이어집니다.
5. **목표 사이클 수**는 경기장 위쪽의 `사이클 − 10 +` 로 10부터 100까지 10 단위로 정합니다. 목표를 채우면 자동으로 끝납니다. 중간에 중지해도 그때까지의 기록이 나옵니다.
6. 플레이 중 화면 오른쪽 위에 **완료/목표 사이클**과 **평균·가장 빠른 사이클 시간**이 실시간으로 보이고, 결과 화면에는 완료 사이클, 평균 사이클, 가장 빠른 사이클, 가장 느린 사이클, 통과한 포인트, 총 시간, 이동 거리가 나옵니다. 랭킹에는 오르지 않습니다.

포인트를 하나도 놓지 않으면 예전처럼 자유 드리블(터치 수·이동 거리)로 동작합니다. 이 모드에서는 가운데 원 대신 코스 화면이 보이므로, 퍽을 새로 등록하려면 보정 > "퍽 다시 등록"을 쓰세요.

## 커뮤니티 (모드 9번)

모드 화면 9번 칸(퍽으로도 고를 수 있음)에서 열립니다. 코스와 기록을 공유하고, 같은 코스로 기록을 겨루는 공간입니다.

- **내 코스 공유**: 자유 연습에서 만든 코스(포인트 배치 + 목표 사이클 수)에 제목과 "이 코스를 연습하면 뭐가 좋아지는지" 설명(200자)을 적어 올립니다. 그 코스를 끝까지 돌아 세운 내 기록(평균·가장 빠른 사이클)이 함께 올라갑니다. `글쓰기` 버튼이나 자유 연습 완주 후 결과 화면의 `코스 공유하기`로 씁니다.
- **이 코스 연습하기**: 글의 버튼을 누르면 그 코스가 자유 연습에 그대로 불려 와 도전이 시작됩니다. 목표 사이클을 완주하면 기록이 그 글의 **기록 게시판(Record board)** 에 자동으로 오릅니다(한 사람당 최고 기록 하나, 평균 사이클 시간이 짧을수록 위, 같으면 가장 빠른 사이클). 기록을 공정하게 비교하려고 포인트를 옮기거나 사이클 수를 바꾸면 도전이 해제됩니다.
- **기록 갱신 자랑**: 1위였던 사람의 기록을 넘어서면 결과 화면에 `New record!` 와 함께 `기록 갱신 자랑하기` 버튼이 나오고, 누르면 "누구의 기록을 몇 초에서 몇 초로 갈아치웠는지"가 담긴 글이 올라갑니다. 그 글의 `이 코스 연습하기`는 원본 코스 글로 이어져 게시판이 하나로 유지됩니다.
- **기록 자랑**: 아케이드 등 점수 게임을 끝까지 마치면 결과 화면의 `기록 자랑하기`로 점수 글을 올릴 수 있고, 다른 사람은 `나도 도전`으로 같은 모드·같은 시간에 바로 맞춰집니다.
- 응원(👏, 한 사람당 한 번), 내 글 삭제(두 번 눌러 확인), 종류별 보기(전체 / 코스 / 기록 자랑)가 있습니다. 처음에는 바로 연습해 볼 수 있는 **예시 코스 3개**가 들어 있습니다.
- 글쓰기·기록 등록·응원은 **로그인**해야 합니다. 게스트는 읽기와 코스 연습만 됩니다.
- **저장 위치**: 랭킹과 같습니다. Firebase를 연결하기 전에는 글과 기록이 **그 기기에만** 저장되어 같은 기기를 쓰는 선수들끼리만 보입니다. Firebase를 연결하면 온라인으로 바뀌도록 `src/community-firebase.js` 와 `firestore.rules` 규칙을 넣어 두었지만, **실제 Firebase 프로젝트로 검증하지 않은 코드**입니다. 또한 누구나 글을 쓸 수 있는 공개 게시판이 되므로, 온라인으로 열 때는 신고·삭제 같은 운영 수단을 함께 마련하는 것이 좋습니다.

## 언어: 한국어 / English

- 첫 화면 오른쪽 위의 **한국어 | English** 버튼(설정에도 있음)으로 바꿉니다. 선택은 기기에 저장되고, 처음 열 때는 브라우저 언어를 따릅니다(한국어 브라우저 = 한국어, 그 밖 = 영어).
- 화면 글자, 안내 문구, 게임 화면(캔버스)의 글자, 카메라 오류 안내까지 모두 바뀝니다. 별명·팀 이름·커뮤니티 글처럼 사용자가 쓴 내용은 번역하지 않습니다.
- 구조: 코드는 한국어 원문을 그대로 쓰고, 화면에 나가는 경계에서 `src/i18n.js` 가 `src/i18n-en.js` 사전으로 바꿉니다. 새 문구를 추가하면 사전에도 넣어야 하며, 빠뜨리면 `node test/i18n-coverage.mjs` (전체 테스트에 포함)가 알려 줍니다.

## 로그인 · 랭킹

- **로그인**: 플레이어 별명 + 숫자 6자리 비밀번호. **회원가입** 때 국가, 팀 이름, 나이, 등번호(선택, 0~99)를 등록하면 연령대(U8·U10·U12·U14·U16·U18·성인·시니어)가 자동 배정됩니다. 게스트로도 플레이할 수 있지만 랭킹에는 오르지 않습니다. 등번호는 별명 옆에 `#87` 처럼 표시됩니다(프로필, 랭킹, 커뮤니티 글).
- **기록**: 게임을 시간 끝까지 마치면 모드별(시간제 모드는 시간별) 개인 최고 기록이 자동 등록되고, 결과 화면에 전체 순위와 연령대 순위가 표시됩니다. 중간에 중지한 게임, 자유 연습, 2인 대결은 등록되지 않습니다.
- **랭킹 화면**: 하단 `랭킹` 버튼. 게임 모드별 × 연령대별 × 범위(전 세계 / 내 국가 / 내 팀)로 볼 수 있고 내 순위가 함께 표시됩니다.

## 인식 방식 (의존성 없음)

1. 카메라 프레임을 240px 폭으로 축소해 매 프레임 분석합니다.
2. **바닥**: 밝고 채도가 낮은(흰색) 픽셀의 행/열 분포로 바닥 영역을 자동 감지합니다. 흰 벽 등으로 오검출되면 **바닥 고정** 버튼으로 현재 영역을 고정하거나, 설정에서 **수동 지정**(모서리 4개 드래그)으로 바꿀 수 있습니다.
3. **퍽**: 바닥 안에서 지정 색(기본 검정)의 픽셀을 연결 성분으로 묶고, 크기·원형도·직전 위치와의 거리로 가장 퍽다운 블롭을 고릅니다. 잠시 가려지면 속도로 예측(주황 원)합니다.
4. **스틱**: 보정에서 블레이드/테이프 색을 지정하면 같은 방식으로 추적합니다(마름모 마커).
5. 바닥 사각형 → 단위 정사각형 호모그래피로 게임 좌표를 만들기 때문에, 콘·타겟이 실제 바닥 위에 놓인 것처럼 원근이 적용됩니다.

## 게임 영역을 원근(3D)으로 맞추기

카메라는 비스듬히 바닥을 보기 때문에 실제 직사각형 바닥은 화면에서 **뒤쪽이 좁은 사다리꼴**로 보입니다. 앱은 이 사다리꼴을 평면 좌표로 펴는 호모그래피를 쓰므로, 영역만 정확히 잡으면 뒤쪽에서 조금 움직여도 실제 거리만큼 퍽이 이동한 것으로 계산됩니다.

- **영역** 버튼(키보드 `A`)을 누르면 네 모서리 핸들(뒤·왼쪽, 뒤·오른쪽, 앞·오른쪽, 앞·왼쪽)과 원근 격자가 나타납니다. 핸들을 실제 바닥 모서리에 끌어다 놓고, 격자가 바닥에 붙어 보이면 **완료**를 누르세요. 편집 중에는 퍽의 바닥 좌표(0~1)가 표시되어 보정 결과를 확인할 수 있습니다.
- 편집 바의 **흰 바닥 자동**은 흰 연습판을 사다리꼴로 자동 감지하고(위쪽 띠·아래쪽 띠의 좌우 끝을 추정), **화면 전체**는 카메라 화면 전체를 씁니다.
- 아케이드 모드의 좌우 이동과 앞뒤(당기기/밀기)도 이 보정된 바닥 좌표를 쓰므로, 영역을 사다리꼴로 맞추면 뒤쪽에서의 움직임이 작게 보이는 문제가 사라집니다.

### 마커 튐 방지

퍽 위치는 등속 예측(알파-베타) 필터로 부드럽게 따라가며, 예측에서 크게 벗어난 측정값은 1~2프레임 무시하고 3프레임 이상 계속되면 실제 이동으로 받아들입니다. 정지 상태의 미세 떨림은 억제되고, 빠르게 칠 때 모션 블러로 퍽이 길어져도 추적이 끊기지 않도록 면적 허용 범위를 속도에 따라 넓힙니다.

## 아무 바닥·아무 물체로 연습하기

- **가운데 원 하나로 끝**: 대기 중에는 화면 가운데에 항상 원이 있습니다. 퍽이 등록되지 않은 상태에서 물체를 원 안에 놓으면 3초 뒤 그 물체가 퍽으로 등록되고, **등록된 퍽**을 원 안에 두면 3초 뒤 게임이 시작됩니다(핸즈프리). 처음 등록한 퍽과 **다른 물체**를 놓으면 시작하지 않고 "등록된 퍽과 다른 물체입니다"라고 안내하며(등록된 퍽 색 견본 표시), 바꾸려면 화면의 "이 물체로 퍽 교체" 버튼이나 보정 > "퍽 다시 등록"을 누르면 됩니다. 등록된 퍽과 같은 색인데 조명·거리 때문에 추적이 끊긴 경우에는 같은 퍽으로 보고 크기만 다시 익힙니다. 앱이 원 바깥 고리의 배경색과 다른 픽셀 덩어리를 찾아 색·크기를 학습하고, 배경과의 색 차이에 맞춰 허용 오차도 자동으로 정합니다. 공, 병뚜껑, 실제 퍽, 테이프 뭉치 등 **배경과 색만 다르면** 무엇이든 됩니다. 스틱 블레이드도 같은 방법으로 지정합니다.
- 물체가 원보다 크면 "카메라에서 더 멀리"라고 안내하고, 3초 동안 물체가 바뀌거나 움직이면 다시 셉니다. 화면을 터치하면 취소됩니다.
- **흰 바닥이 없어도 됩니다**: 흰 바닥이 3초 넘게 안 보이면 카메라 화면 전체를 게임 영역으로 자동 사용하고, 흰 연습판이 다시 보이면 그 영역으로 돌아갑니다(상태 칩에 "영역(전체화면)" 표시).
- 같은 색 물체가 배경에 여러 개 있으면 혼동할 수 있으니, 매트와 뚜렷하게 다른 색 하나를 고르세요.

## 추적 안정성 (이전 프로젝트 리뷰에서 반영한 사항)

- **같은 색 방해물 방지**: 탐색은 바닥 영역 안으로 제한되고, 보정 터치 위치를 추적 시작점으로 사용해 처음부터 다른 물체에 붙지 않습니다. 추적 중에는 예측 위치와 가까운 덩어리를 우선하고, 놓친 뒤 다시 찾을 때는 마지막 퍽과 크기가 비슷한 것만 받습니다. 바닥 밖으로 나간 퍽은 "놓침"으로 처리합니다.
- **강타 대응**: 스틱이 퍽 근처에 있거나 퍽이 빠르게 움직일 때만 탐색 범위를 넓히고 속도로 다음 위치를 예측합니다. 항상 넓히면 방해물에 붙는 부작용이 있어 조건부로만 넓힙니다. **스틱 색을 지정하면 타격 직후에도 퍽을 따라갑니다.**
- **조명 변화**: 주황·파랑처럼 채도가 높은 색은 RGB 대신 정규화 색도로 비교해, 어두워지거나 그림자가 져도 인식이 유지됩니다. 검정 퍽은 RGB 거리로 비교합니다.
- **반사광으로 갈라진 덩어리 병합**, **손상된 저장값 검증**, **카메라 끊김·영상 정지 감지**, **화면 가림 시 안내**를 포함합니다.
- 결과 화면에 **퍽 추적률**이 표시됩니다. 실제 환경에서 이 값과 fps를 보고 슬라이더를 조정하세요.

## 사용 준비

1. 아이패드를 거치대에 세우고 흰 바닥(연습판)이 화면에 크게 들어오게 각도를 맞춥니다. 조명은 고르게, 바닥에 강한 그림자가 없을수록 좋습니다.
2. 앱을 열고 **카메라 시작** → 바닥이 파란 점선으로 표시되는지 확인합니다.
3. **보정** → "퍽 터치로 지정" 후 화면 속 퍽을 터치합니다(검정 퍽은 기본값으로도 동작). 스틱은 블레이드에 **주황·파랑 등 눈에 띄는 색 테이프**를 감고 같은 방법으로 지정하세요. 흰색·검정 테이프는 바닥/퍽과 구분되지 않습니다.
4. 설정 > "인식 마스크 표시"를 켜면 바닥(파랑)·퍽(빨강)·스틱(초록) 마스크를 보며 밝기/허용 오차 슬라이더를 조정할 수 있습니다.
5. **모드** 선택 후 **시작**.

## 휴대폰을 거치대에 세워 플레이

### 방법 A. 컴퓨터를 서버로 (같은 Wi-Fi)

1. 컴퓨터에서 프로젝트 폴더를 열고 `python3 serve.py` (Windows는 `python serve.py`)를 실행합니다.
2. 터미널에 **휴대폰에서 열 주소가 숫자 IP로** 표시됩니다. 예: `https://192.168.0.12:8443`. `<컴퓨터IP>` 같은 글자가 아니라 이 숫자 주소를 휴대폰 브라우저에 그대로 입력하세요. (`pip install qrcode` 를 설치해 두면 QR 코드도 표시됩니다.)
3. 인증서 경고가 뜨면 iPhone Safari는 "세부사항 보기 > 이 웹 사이트 방문", Android Chrome은 "고급 > 이동"으로 계속합니다.
4. 안 열리면 순서대로 확인: 휴대폰과 컴퓨터가 같은 Wi-Fi인지(휴대폰 데이터 끄기) → 처음 실행 시 뜨는 방화벽 팝업에서 Python 허용(개인 네트워크) → 공유기의 "AP 격리/기기 간 통신 차단" 해제 → 포트 변경(`python3 serve.py 9443`).

### 방법 B. GitHub Pages 링크로 바로 열기 (컴퓨터 없이, 추천)

`main` 브랜치에 푸시하면 `.github/workflows/pages.yml` 이 **https://ochodoit.github.io/semple/** 에 자동 배포합니다. 워크플로가 Pages를 자동 활성화하지 못하면 저장소 **Settings > Pages > Source**를 `GitHub Actions`로 한 번만 바꿔 주세요. HTTPS라 휴대폰 카메라가 바로 허용되고 인증서 경고도 없습니다.

**접속 코드(본인만 사용)**: 공개 주소이므로 첫 화면에서 접속 코드를 묻습니다. 한 번 맞게 입력하면 그 기기에서는 다시 묻지 않습니다. 코드를 바꾸려면 아래를 실행하고 커밋·푸시하세요(빈 문자열이면 잠금 해제).

```bash
node tools/set-pin.mjs 5678
```

GitHub 무료 계정에서는 Pages 사이트 자체를 비공개로 만들 수 없어서(Enterprise 전용) 이 클라이언트 측 잠금으로 대신합니다. 소스를 읽으면 우회할 수 있는 수준이므로 개인 정보가 없는 게임용 보호로 생각하세요.

### 플레이 설정

1. (방법 A의 경우) 같은 Wi-Fi의 컴퓨터에서 `python3 serve.py` 를 실행하고, 휴대폰 브라우저에서 터미널에 표시된 주소를 엽니다.
2. 홈 화면에 추가하면 주소창 없이 전체화면으로 실행됩니다. 세로·가로 모두 지원합니다.
3. 거치대에 세우고 **전면 카메라**(기본)로 자신과 연습 공간이 보이게 둡니다. 화면이 거울처럼 보이며, 🔄 버튼으로 후면 카메라로 바꿀 수 있습니다(후면은 거울 모드 자동 해제).
4. 설정 > 게임 영역은 흰 바닥이 크게 보이면 자동 감지, 아니면 `카메라 화면 전체`로 두세요.
5. **핸즈프리 시작**: 멀리 떨어져 있어도 퍽을 가운데 초록 원 안에 3초 두면 게임이 시작되고, 게임이 끝난 뒤에도 같은 방법으로 다시 시작됩니다(설정에서 끌 수 있음). 아케이드 모드는 이 경우 카운트다운을 생략하고 바로 GO 합니다.
6. 플레이 중 화면이 꺼지지 않도록 Wake Lock을 요청합니다(저전력 모드에서는 거부될 수 있으니 자동 잠금을 길게 설정하세요).
7. 세로 화면에서는 장애물 낙하 속도를 화면 비율에 맞게 보정해 가로와 같은 체감 속도를 유지합니다.

## 카메라가 연결되지 않을 때

"카메라 시작"이 실패하면 첫 화면에 오류 이름과 해결 순서, 감지된 카메라 목록이 표시됩니다. 자주 있는 원인:

| 증상 | 해결 |
| --- | --- |
| 권한 거부 (NotAllowedError) | Chrome/Edge: 주소창 왼쪽 자물쇠 아이콘 > 카메라 "허용" > 새로고침. Windows: 설정 > 개인 정보 및 보안 > 카메라 > "카메라 액세스"와 "앱이 카메라에 액세스하도록 허용" 켜기. macOS: 시스템 설정 > 개인정보 보호 및 보안 > 카메라 > 브라우저 켜기 |
| 열 수 없음 / 응답 없음 (NotReadableError, TimeoutError) | Zoom·Teams·카카오톡·카메라 앱·OBS 등 카메라를 쓰는 프로그램을 트레이까지 완전히 종료, 다른 탭 확인, 브라우저 재시작 |
| 카메라 없음 (NotFoundError) | 노트북 카메라 가림막·Fn 카메라 끄기 키 확인, 장치 관리자에서 카메라 사용 여부 확인 |
| 선택한 카메라 사용 불가 (OverconstrainedError) | 목록에서 다른 카메라 선택 후 "다시 시도" (IR/적외선 카메라는 피하세요) |

"진단 정보 복사" 버튼으로 복사한 내용을 전달하면 원인을 빠르게 찾을 수 있습니다.

## 노트북 웹캠으로 플레이

노트북 카메라는 바닥을 내려다보지 않고 정면을 보기 때문에 설정 몇 가지를 바꾸면 잘 동작합니다.

1. 노트북을 바닥 가까이(또는 낮은 의자 위에) 두고 화면을 뒤로 젖혀 연습 공간이 화면 아래쪽 2/3를 차지하게 합니다. 거울 모드(기본 켜짐)라 화면이 거울처럼 보입니다.
2. **설정 > 게임 영역**
   - 흰 연습판이 화면에 크게 보이면 `흰 바닥 자동 감지` 그대로 두세요.
   - 흰 바닥이 없거나 흰 벽이 같이 잡히면 `카메라 화면 전체` 또는 `수동 지정`으로 바꾸세요. 자동 감지가 4초 넘게 실패하면 앱이 안내 메시지를 띄웁니다.
3. **설정 > 인식 해상도**: 웹캠에서 퍽이 작게 보이면 `높음(320)` 또는 `최고(400)`으로 올리세요. 처리 시간은 240px 기준 약 2ms라 여유가 있습니다.
4. **보정**: 어두운 바닥에서는 검정 퍽이 안 보이므로 주황 볼이나 밝은 색 연습용 퍽을 쓰고 화면에서 클릭해 색을 지정하세요. 스틱 블레이드에는 다른 색 테이프를 감고 지정하세요.
5. **설정 > 조작 대상**: 퍽이 없으면 `스틱 블레이드`로 바꿔 블레이드만으로 아케이드와 드릴을 할 수 있습니다.
6. 실행은 아래처럼 localhost로 열면 HTTPS 없이도 카메라가 허용됩니다(Chrome, Edge, Safari).

```bash
python3 serve.py --http        # macOS/Linux
python serve.py --http         # Windows
# -> http://localhost:8080
```

조작은 마우스 클릭과 키보드(`Space` 시작·중지, `F` 전체화면 등) 모두 됩니다. 창을 최소화하거나 다른 창으로 완전히 가리면 브라우저가 프레임 처리를 멈추므로 전체화면(`F`)을 권장합니다.

## 실행

카메라(getUserMedia)는 **HTTPS 또는 localhost**에서만 동작합니다.

```bash
# 같은 Wi-Fi의 아이패드에서 테스트 (자체 서명 인증서 자동 생성, openssl 필요)
python3 serve.py
# -> https://<컴퓨터IP>:8443 을 아이패드 Safari에서 열고 인증서 경고를 통과

# 데스크톱 로컬 테스트만 할 때
python3 serve.py --http   # http://localhost:8080
```

Firebase Studio 미리보기나 Firebase Hosting / GitHub Pages 등 HTTPS 호스팅에 올리면 바로 사용할 수 있습니다.
iPadOS에서는 Safari 공유 메뉴 → **홈 화면에 추가**로 전체화면 앱처럼 실행하세요.
